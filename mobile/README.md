# Приложение МояДача

Flutter-клиент. MVP выходит только под Android; iOS — следующая платформа
([ADR-0003](../docs/adr/0003-flutter-for-the-client.md)), поэтому папки `ios/`
пока нет: она создаётся `flutter create --platforms ios .`, когда дойдёт дело.

Клиент API не пишется руками, а генерируется из `specs/openapi.yaml`
в `packages/moya_dacha_api` ([ADR-0008](../docs/adr/0008-dart-client-generation.md)).

## Работа с приложением

Команды запускаются из корня репозитория:

| | |
|---|---|
| `make app-get` | зависимости |
| `make app-analyze` | статический анализ |
| `make app-apk` | debug-APK (адрес стенда — как у эмулятора) |
| `make apk-phone` | APK для телефона: адрес этой машины в локальной сети |
| `make generate` | перегенерировать клиент из контракта |

Показать фичу в эмуляторе — одна команда на сценарий показа
([ADR-0009](../docs/adr/0009-demo-story-per-feature.md)):

    make stories                  # что можно показать
    make story STORY=000-status   # стенд, приложение, снимок экрана

Для интерактивного показа, когда стенд уже поднят:

    flutter run                   # на эмуляторе, стенд виден как 10.0.2.2

Адрес API зашивается при сборке и по умолчанию равен `http://10.0.2.2:8080/api`
— это `127.0.0.1` машины-хоста изнутри эмулятора. Для телефона нужен адрес
машины в локальной сети, его подставляет `make apk-phone`; вручную —

    flutter run --dart-define=API_BASE_URL=http://192.168.1.10:8080/api

Подробнее про стенд, показ и установку на телефон —
[demo/README.md](../demo/README.md).

## Что в приложении есть

Один экран состояния: он спрашивает у сервиса `/api/health` и показывает,
отвечает ли тот и жива ли база. Продуктовых экранов нет, потому что в контракте
ещё нет продуктовых эндпоинтов — они появятся вместе со спецификациями фич
из [specs/000-overview.md](../specs/000-overview.md).

Автотестов у клиента нет намеренно: гейт проекта — интеграционные тесты
сервера, а UI-тесты на мобильном клиенте решено не писать
([ADR-0002](../docs/adr/0002-tests-as-the-only-gate.md)). Целостность пути
«приложение → сервис → база» проверяет e2e-прогон в эмуляторе на CI, а то,
что фича выглядит как задумано, смотрит человек по сценарию показа
([ADR-0009](../docs/adr/0009-demo-story-per-feature.md)).
