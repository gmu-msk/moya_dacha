# Приложение МояДача

Flutter-клиент. MVP выходит только под Android; iOS — следующая платформа
([ADR-0003](../docs/adr/0003-flutter-for-the-client.md)), поэтому папки `ios/`
пока нет: она создаётся `flutter create --platforms ios .`, когда дойдёт дело.

Клиент API не пишется руками, а генерируется из `specs/openapi.yaml`
в `packages/moya_dacha_api` ([ADR-0008](../docs/adr/0008-dart-client-generation.md)).

## Работа с приложением

Команды запускаются из корня репозитория:

| | |
|---|---|
| `make app-get` | зависимости |
| `make app-analyze` | статический анализ |
| `make app-apk` | debug-APK (адрес стенда — как у эмулятора) |
| `make apk-phone` | APK для телефона: адрес этой машины в локальной сети |
| `make app-test` | экраны собираются (не гейт, [ADR-0012](../docs/adr/0012-theme-and-shared-widgets.md)) |
| `make generate` | перегенерировать клиент из контракта |

Показать фичу в эмуляторе — одна команда на сценарий показа
([ADR-0009](../docs/adr/0009-demo-story-per-feature.md)):

    make stories                  # что можно показать
    make story STORY=000-status   # стенд, приложение, снимок экрана

Для интерактивного показа, когда стенд уже поднят:

    flutter run                   # на эмуляторе, стенд виден как 10.0.2.2

Адрес API человек задаёт на экране «Сервер» — нажатием на точку состояния
сервиса в заголовке ([ADR-0013](../docs/adr/0013-testing-from-a-phone.md)). Так
одна и та же сборка ходит на любой стенд: временный из PR, на машине
в локальной сети, потом на настоящий сервер.

Пока адрес не задан, работает зашитый при сборке — по умолчанию
`http://10.0.2.2:8080/api`, то есть `127.0.0.1` машины-хоста изнутри
эмулятора. Задать его при сборке:

    flutter run --dart-define=API_BASE_URL=http://192.168.1.10:8080/api

Выбранный адрес лежит рядом с токеном сессии, в приватном хранилище
приложения (`lib/server.dart`). При смене адреса сессия стирается: токен
живёт на том сервере, где его выдали.

Подробнее про стенд, показ и установку на телефон —
[demo/README.md](../demo/README.md).

## Что в приложении есть

Вход по номеру телефона ([specs/001-auth.md](../specs/001-auth.md)): экран
входа (номер → код), экран вошедшего пользователя и выход. Токен сессии
лежит в приватном хранилище приложения и переживает перезапуск, поэтому
входят один раз ([ADR-0010](../docs/adr/0010-opaque-session-tokens.md)).

Профиль ([specs/002-profile.md](../specs/002-profile.md)): экран знакомства
для того, у кого имени ещё нет, и экран профиля — имя, «о себе» и аватар
из галереи. Ссылку на аватар сервис отдаёт относительной, приложение
достраивает её до адреса сервиса
([ADR-0011](../docs/adr/0011-files-behind-storage-interface.md)).

Пост ([specs/003-posts.md](../specs/003-posts.md)): экран создания поста
(до четырёх фотографий из галереи и подпись) и экран самого поста.
Фотографии уменьшаются перед отправкой и уходят на сервис по одной,
поэтому не долетевшую можно переотправить, не собирая пост заново.

Лента ([specs/004-feed.md](../specs/004-feed.md)): главный экран. Посты
всех дачников, новые сверху, страницами по мере прокрутки; жест вниз
обновляет. В ленте видна первая фотография поста и начало подписи,
целиком пост открывается нажатием. Выход из приложения переехал отсюда
в профиль: на главном экране место постам.

Лайки ([specs/005-likes.md](../specs/005-likes.md)): сердечко с числом
под постом в ленте и на самом посте. Оно отзывается сразу, не дожидаясь
сервиса, и возвращается как было, если сервис ответил ошибкой.

В заголовке экрана входа и главного — точка состояния сервиса: она
спрашивает `/api/health` и показывает цветом, отвечает ли сервис и жива ли
база, а когда не отвечает — ещё и значком перечёркнутого облака. По ней же
прогон в эмуляторе понимает, что приложение доехало до сервиса. Рядом
круглая стрелка «проверить ещё раз», а нажатие на саму точку открывает
экран «Сервер», где меняют адрес. На экранах, где человек делает своё
дело — профиль, новый пост, сам пост, — точки нет: она там ни к чему.

Остальные экраны появятся вместе со следующими фичами из
[specs/000-overview.md](../specs/000-overview.md).

Гейт проекта — интеграционные тесты сервера, а UI-тесты на мобильном
клиенте решено не писать ([ADR-0002](../docs/adr/0002-tests-as-the-only-gate.md)).
В `test/` лежат только две вещи, которые иначе ловятся лишь прогоном
в эмуляторе: что каждый экран собирается в обеих темах и при вдвое
увеличенном системном шрифте
([ADR-0012](../docs/adr/0012-theme-and-shared-widgets.md)), что введённый
руками адрес сервера разбирается верно, что сердечко ведёт себя как надо
и что «когда это было» пишется по-русски верно во всех падежах. Целостность пути
«приложение → сервис → база» проверяет e2e-прогон в эмуляторе на CI, а то,
что фича выглядит как задумано, смотрит человек по сценарию показа
([ADR-0009](../docs/adr/0009-demo-story-per-feature.md)).
