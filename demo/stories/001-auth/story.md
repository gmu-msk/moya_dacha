# Вход по номеру телефона

## Что показываем
Человек открывает приложение, вводит номер телефона, получает код и
попадает внутрь. Регистрация и вход — одно действие: новый номер заводит
пользователя, известный — просто впускает.

Код на стенде фиксированный — **0000**: SMS-провайдер не выбран, и стенд
поднимается с `AUTH_FIXED_CODE=0000`, чтобы фичу можно было показать без
SMS (specs/001-auth.md). В проде код случайный и уходит в лог сервиса,
откуда его выдают вручную.

## Данные
Три номера на стенде уже зарегистрированы (общие данные стенда,
`demo/seed/001-users.sql`):

- `+7 900 000-00-01`
- `+7 900 000-00-02`
- `+7 900 000-00-03`

Своих данных сценарию не нужно: второй случай — вход с номера, которого
на стенде нет, — показывается любым другим номером, придуманным на месте.

## Что проверить руками
- [ ] На экране входа поле «Номер телефона», внизу «Сервер отвечает, база жива»
- [ ] Номер `+7 900 000-00-01` и «Получить код» — появляется поле для кода
- [ ] Код `0000` — приложение пишет «Вы вошли» и показывает `+79000000001`
- [ ] «Выйти» возвращает на экран входа
- [ ] Номер `8 900 000 00 01` (без плюса и скобок) и код `0000` — тот же
      пользователь, тот же номер на экране
- [ ] Незнакомый номер, например `+7 900 555-77-88`, и код `0000` —
      «Добро пожаловать!»: пользователь завёлся этим входом
- [ ] Неверный код `1111` — «Код не подошёл», экран не меняется
- [ ] «Получить код» дважды подряд на один номер — «Код уже отправлен.
      Подождите минуту и попробуйте снова»
- [ ] Номер `+7 495 123-45-67` (городской) — «Это не похоже на номер
      мобильного телефона»
- [ ] Закрыть приложение и открыть заново — оно открывается сразу внутри,
      без входа
- [ ] В логах стенда виден выданный код: `make demo-logs`, строка
      «код подтверждения»
