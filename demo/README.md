# Демо-стенд

Локальный стенд, на котором приложение можно показать: одна команда поднимает
Postgres, накатывает миграции, наливает демо-данные и запускает сервис.

    make demo

Команда сама дождётся ответа от сервиса и напечатает адреса. Нужен только
Docker — Go и Postgres на машине не требуются.

    API                 http://127.0.0.1:8080/api
    Проверка живости    http://127.0.0.1:8080/api/health
    Postgres            postgres://moya_dacha:moya_dacha@127.0.0.1:55433/moya_dacha

Порты слушаются только на `127.0.0.1`: стенд виден с этой машины, а не из сети.

## Команды

| | |
|---|---|
| `make demo` | поднять (или пересобрать и поднять) стенд |
| `make demo-logs` | логи сервиса |
| `make demo-psql` | консоль `psql` в базе стенда |
| `make demo-down` | остановить; данные в базе остаются |
| `make demo-reset` | остановить и стереть базу стенда |

## Что показывать сейчас

Продуктовых эндпоинтов пока нет: в контракте только `/health`. Стенд
показывает, что каркас собран целиком — контракт, сгенерированный роутинг,
реализация и настоящая Postgres отвечают по HTTP:

    curl http://127.0.0.1:8080/api/health
    {"status":"ok"}

То же самое показывает приложение: единственный его экран спрашивает у стенда
`/api/health` и говорит, отвечает ли сервис и жива ли база.

Дальше эндпоинты появляются на стенде сами: он собирает сервис из текущего
кода, а миграции берёт из `backend/migrations`.

## Приложение в эмуляторе

Полный путь — эмулятор, приложение, сервис, база — показывается так:

    make demo                     # стенд
    make app-apk                  # debug-APK
    make demo-e2e                 # поставить в эмулятор и проверить

Эмулятор должен быть запущен заранее (`adb devices` показывает устройство).
`make demo-e2e` ставит APK, запускает приложение, ждёт в логах ответ
`/api/health`, кладёт снимок экрана в `demo/out/` и падает, если ответа нет.
Тот же скрипт гоняет CI — там эмулятор поднимается сам, а снимок экрана
прикладывается к прогону.

Для интерактивного показа удобнее `flutter run` из `mobile/`.

Адреса стенда с точки зрения клиента:

- Android-эмулятор — `http://10.0.2.2:8080/api` (`10.0.2.2` — это `127.0.0.1`
  машины-хоста изнутри эмулятора), это адрес по умолчанию;
- телефон в той же сети — `http://<IP машины>:8080/api` через
  `--dart-define=API_BASE_URL=...`; для этого в `docker-compose.demo.yml`
  у сервиса `api` надо убрать привязку к `127.0.0.1` и открыть порт наружу.

Обычный HTTP без TLS Android не разрешает, поэтому `usesCleartextTraffic`
включён — но только в debug-манифесте: в проде перед сервисом стоит Caddy
с сертификатом.

## Демо-данные

Всё, что лежит в `demo/seed/*.sql`, применяется к базе после миграций,
по порядку имён файлов — см. [seed/README.md](seed/README.md).

## Как это устроено

`docker-compose.demo.yml` описывает четыре сервиса:

1. `postgres` — Postgres 17, мажорная версия та же, что в тестах и на VPS;
   данные в именованном томе;
2. `migrate` — одноразовый шаг `goose ... up`, отдельно от старта приложения,
   как и в проде ([ADR-0005](../docs/adr/0005-no-staging-forward-only-migrations.md));
3. `seed` — одноразовый шаг, применяющий `demo/seed/*.sql`;
4. `api` — сам сервис, поднимается после обоих шагов.

Образ из `demo/Dockerfile` собирается только для стенда и никуда
не публикуется: в проде контейнеров нет — один бинарник под systemd
([ADR-0004](../docs/adr/0004-binary-and-systemd-in-production.md)).

Стенд не заменяет прод и не является staging-средой: staging в проекте нет
осознанно (ADR-0005). Настоящий сервер описан в [deploy/](../deploy/README.md).
