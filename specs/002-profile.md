# Спецификация: профиль пользователя

## Статус
Готово

## Зачем (контекст)
После входа ([001-auth](001-auth.md)) пользователь — это только номер
телефона, а номер в продукте не показывают никогда ([CONTEXT.md](../CONTEXT.md)).
Чтобы в ленте, под комментарием и под лайком было видно, кто это, у
пользователя должны быть имя и лицо.

Профиль — это имя, аватар и короткое «о себе». Имя неуникально: дачников
двадцать, они знают друг друга, и второй Николай никому не мешает.

Имя обязательно. Пользователь, который только что зарегистрировался,
попадает на экран знакомства и заполняет имя до того, как увидит всё
остальное: безымянный автор в ленте — это дыра, которую потом нечем
закрыть.

## Пользовательский сценарий

**Дано:** пользователь только что вошёл впервые (`is_new_user`).

1. Приложение показывает экран «Как вас зовут».
2. Пользователь вводит имя, при желании — «о себе», и сохраняет.
3. Пользователь может выбрать аватар из галереи телефона. Сервис
   уменьшает картинку и сохраняет её.
4. Дальше профиль открывается с главного экрана: там видно имя, аватар
   и «о себе», и всё это можно поменять.

**Тогда:** имя и аватар — это то, чем пользователь подписан везде, где
его показывают.

**Если пользователь уже входил раньше** — экран знакомства не появляется:
имя у него уже есть.

## Функциональные требования

1. Пользователь видит свой профиль: имя, «о себе», аватар, номер телефона
   и дату регистрации.
2. Пользователь задаёт и меняет имя. Имя обязательно: от 1 до 50 символов
   после обрезки пробелов по краям.
3. Пользователь задаёт и меняет «о себе»: до 200 символов, можно пустым.
4. Имя и «о себе» — одна строка: переводы строк и прочие управляющие
   символы не принимаются.
5. Пользователь ставит аватар, загружая картинку: JPEG или PNG,
   не больше 5 МБ.
6. Тип картинки определяется по её содержимому, а не по тому, что сказал
   клиент: файл, который не является картинкой, отклоняется.
7. Аватар уменьшается до 512×512 (пропорции сохраняются, картинка меньше
   не увеличивается) и пересохраняется в JPEG. Так аватар весит килобайты,
   а не мегабайты, и вместе с перекодированием из файла уходит всё, что
   не является картинкой, — EXIF в том числе.
8. Новый аватар заменяет прежний: старый файл удаляется.
9. Пользователь может убрать аватар. Убрать несуществующий аватар — не
   ошибка.
10. Аватар доступен по ссылке, которую сервис возвращает вместе с
    профилем. Ссылка может быть относительной (`/media/avatars/…`) —
    клиент достраивает её до адреса сервиса.
11. Файлы лежат за интерфейсом хранилища: в MVP это локальный диск,
    и раздаёт их сам сервис. Переезд на S3-совместимое хранилище — новая
    реализация интерфейса, контракт при этом не меняется
    ([ADR-0011](../docs/adr/0011-files-behind-storage-interface.md)).
12. Всё перечисленное доступно только владельцу профиля, по токену из
    [001-auth](001-auth.md).

## Вне рамок (Out of scope)

- **Чужой профиль и публичное представление автора.** Автор появляется
  там, где есть что подписывать, — в ленте ([004-feed](000-overview.md)).
  Отдельный экран чужого профиля до ленты некуда открыть из приложения,
  а эндпоинт, который нельзя показать человеку, — это не фича.
- Обрезка и поворот аватара в приложении: берём картинку как есть.
- Несколько картинок, обложка профиля, темы оформления.
- Уникальные имена, ники, поиск людей по имени.
- Смена номера телефона, удаление аккаунта.
- Проверка содержимого картинки (модерация): жалобы — это
  [008-reports](000-overview.md), автоматической модерации в MVP нет.

## API / контракт данных

Контракт целиком — в [specs/openapi.yaml](openapi.yaml).

### `GET /api/me` — мой профиль

```
Authorization: Bearer <токен>
Response 200: {
  "id": "uuid",
  "phone": "+79001234567",
  "created_at": "2026-09-20T10:00:00Z",
  "name": "Николай",
  "about": "Три сотки под картошку",
  "avatar_url": "/media/avatars/6f1c….jpg"
}
Response 401: { "code": "unauthorized", "message": "..." }
```

`name` и `about` — пустые строки, пока не заданы; `avatar_url`
отсутствует или `null`, пока аватара нет. Пустое имя означает, что
пользователь ещё не знакомился: приложение показывает ему экран
знакомства.

### `PUT /api/me` — изменить имя и «о себе»

```
Authorization: Bearer <токен>
Request:  { "name": "Николай", "about": "Три сотки под картошку" }
Response 200: профиль целиком, как у GET /api/me
Response 400: { "code": "invalid_name",  "message": "..." }
Response 400: { "code": "invalid_about", "message": "..." }
Response 401: { "code": "unauthorized",  "message": "..." }
```

Это замена обоих полей сразу, а не частичное изменение: `about`
без значения очищает поле.

### `PUT /api/me/avatar` — поставить аватар

```
Authorization: Bearer <токен>
Content-Type: multipart/form-data, поле `file` — картинка
Response 200: профиль целиком, с новой ссылкой на аватар
Response 400: { "code": "invalid_image",    "message": "..." }
Response 401: { "code": "unauthorized",     "message": "..." }
Response 413: { "code": "image_too_large",  "message": "..." }
```

### `DELETE /api/me/avatar` — убрать аватар

```
Authorization: Bearer <токен>
Response 200: профиль целиком, уже без аватара
Response 401: { "code": "unauthorized", "message": "..." }
```

### Ошибки

| код | статус | когда |
|---|---|---|
| `invalid_name` | 400 | имя пустое, длиннее 50 символов или не одна строка |
| `invalid_about` | 400 | «о себе» длиннее 200 символов или не одна строка |
| `invalid_request` | 400 | тело запроса не разбирается; в загрузке нет поля `file` |
| `invalid_image` | 400 | файл не JPEG и не PNG или не читается как картинка |
| `image_too_large` | 413 | картинка больше 5 МБ |
| `unauthorized` | 401 | нет токена или он недействителен |

## Модель данных

К таблице `users` из [001-auth](001-auth.md) добавляются три поля:

```
users
  ...
  name       text NOT NULL DEFAULT ''   -- пусто, пока пользователь не знакомился
  about      text NOT NULL DEFAULT ''
  avatar_key text                       -- NULL, если аватара нет
```

`avatar_key` — ключ файла в хранилище (`avatars/<случайное имя>.jpg`),
а не ссылка: ссылку сервис строит из ключа сам. Поэтому переезд на другое
хранилище не требует переписывать данные.

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Имя с пробелами по краям | пробелы обрезаются, сохраняется обрезанное |
| Имя из одних пробелов или пустое | `400 invalid_name` |
| Имя длиннее 50 символов | `400 invalid_name` |
| Имя из 50 символов кириллицы | сохраняется: считаются символы, а не байты |
| Перевод строки или табуляция в имени или «о себе» | `400 invalid_name` / `400 invalid_about` |
| Пустое «о себе» | допустимо, поле очищается |
| «О себе» длиннее 200 символов | `400 invalid_about` |
| Аватар — PNG | принимается, сохраняется как JPEG |
| Аватар — текстовый файл с именем `photo.jpg` | `400 invalid_image` |
| Аватар — GIF или WebP | `400 invalid_image`: в MVP только JPEG и PNG |
| Аватар больше 5 МБ | `413 image_too_large` |
| Картинка меньше 512×512 | сохраняется как есть, не увеличивается |
| Загрузка без поля `file` | `400 invalid_request` |
| Второй аватар подряд | ссылка меняется, старый файл удаляется |
| Удаление аватара, когда его нет | `200`, профиль без аватара |
| Любой из запросов без токена | `401 unauthorized` |
| Ссылка на аватар чужого пользователя | угадать нельзя: имя файла случайное |
