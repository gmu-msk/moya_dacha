# Спецификация: лайки

## Статус
В работе

## Зачем (контекст)
Лента есть ([004-feed](004-feed.md)), но сказать соседу «красиво» пока
нечем: комментарий — это целое дело, а чаще всего человеку хочется
ровно одного — отметить, что он увидел и ему понравилось. Лайк — самый
дешёвый способ, и по нему же видно, живёт ли лента: гипотеза проекта
проверяется не только тем, что люди постят, но и тем, что они друг друга
замечают ([000-overview](000-overview.md)).

Лайк — отметка одобрения, поставленная пользователем посту. Один
пользователь — не больше одного лайка на пост, и его можно снять.
У комментариев лайков нет ([CONTEXT.md](../CONTEXT.md)).

## Пользовательский сценарий

**Дано:** пользователь вошёл и смотрит ленту.

1. Под постом он видит сердечко и число: сколько человек отметили пост
   и отмечал ли его он сам.
2. Нажимает сердечко — оно закрашивается, число растёт на единицу.
3. Нажимает ещё раз — лайк снимается, число уменьшается.
4. То же сердечко и на экране самого поста.

**Тогда:** автор видит, что его пост заметили, а читателю, чтобы сказать
об этом, хватило одного касания.

**Если связь пропала** — сердечко возвращается в прежнее состояние и
рядом видно, что отметить не удалось.

## Функциональные требования

1. Вошедший пользователь ставит посту лайк и снимает его. Один
   пользователь — не больше одного лайка на один пост
   ([CONTEXT.md](../CONTEXT.md)).
2. Лайкнуть можно любой пост, включая свой: лента одна на всех, а
   запрет на «лайк себе» ничего не бережёт и требует объяснения.
3. Поставить лайк дважды — то же, что поставить один раз; снять лайк,
   которого не было, — не ошибка. Оба запроса отвечают тем, что в итоге
   стало: на дачной связи повтор запроса — обычное дело, и второй раз
   он не должен ломаться.
4. У поста есть число лайков и признак «я отметил». Они приходят везде,
   где приходит пост: в ленте, на самом посте и в ответе на сам лайк
   ([004-feed](004-feed.md), требование 5).
5. Кто именно лайкнул, посмотреть нельзя: списка лайкнувших в MVP нет.
   Автор видит число, а не имена.
6. Лайк живёт вместе с постом: удаление поста
   ([007-deletion](000-overview.md)) уносит и лайки.
7. Число лайков считается по факту, отдельного счётчика в посте нет:
   на два десятка дачников и ленту в двадцать постов это дешевле, чем
   держать счётчик согласованным.
8. Ответ на лайк — пост целиком, как и везде: у клиента одно
   представление поста и один способ его обновить
   ([002-profile](002-profile.md), тот же приём с профилем).
9. В приложении сердечко отзывается сразу, не дожидаясь сервиса, а если
   сервис ответил ошибкой — возвращается как было, и человек видит, что
   не получилось. Ждать секунду на каждое касание нельзя: лайк тем и
   хорош, что мгновенный.
10. Лайк виден любому вошедшему; без токена лайков нет, как и всего
    остального ([001-auth](001-auth.md)).

## Вне рамок (Out of scope)

- **Кто лайкнул**: списка людей нет, есть число.
- **Лайки комментариев**: их нет вовсе ([CONTEXT.md](../CONTEXT.md)).
- Другие реакции: сердечко одно, «огонь» и «класс» не заводим.
- Уведомление автору о лайке: push-уведомлений в MVP нет
  ([000-overview](000-overview.md)).
- Сортировка ленты по числу лайков: порядок ленты — только время
  ([004-feed](004-feed.md)).
- Лайки в ответе как отдельный ресурс (`GET /api/posts/{id}/likes`):
  показывать по ним нечего.

## API / контракт данных

Контракт целиком — в [specs/openapi.yaml](openapi.yaml).

### `PUT /api/posts/{postId}/like` — поставить лайк

```
Authorization: Bearer <токен>

Response 200: пост целиком, как у GET /api/posts/{id}
Response 401: { "code": "unauthorized",   "message": "..." }
Response 404: { "code": "post_not_found", "message": "..." }
```

### `DELETE /api/posts/{postId}/like` — снять лайк

```
Authorization: Bearer <токен>

Response 200: пост целиком, как у GET /api/posts/{id}
Response 401: { "code": "unauthorized",   "message": "..." }
Response 404: { "code": "post_not_found", "message": "..." }
```

Оба запроса идемпотентны: важно не то, что изменилось, а то, что стало.
Поэтому оба отвечают постом, а не пустым телом, — клиенту не нужно
досчитывать число самому.

### Пост в ответе

К посту добавились два поля, и они приходят везде, где приходит пост:

```
{
  "id": "uuid",
  "created_at": "2026-09-20T10:00:00Z",
  "caption": "Первая клубника в этом году",
  "author": { … },
  "media": [ … ],
  "likes": 3,
  "liked": true
}
```

`likes` — сколько людей отметили пост. `liked` — отметил ли его тот, кто
спрашивает. Оба поля обязательны: пост без лайков приходит с `"likes": 0`
и `"liked": false`, а не без полей.

### Ошибки

| код | статус | когда |
|---|---|---|
| `unauthorized` | 401 | нет токена или он недействителен |
| `post_not_found` | 404 | поста с таким идентификатором нет |

## Модель данных

```
post_likes
  post_id    uuid        not null references posts(id) on delete cascade
  user_id    uuid        not null references users(id) on delete cascade
  created_at timestamptz not null default now()
  primary key (post_id, user_id)
```

Первичный ключ из пары — это и есть «не больше одного лайка на пост от
человека»: второй такой строки база не примет, и проверять это в коде
не нужно. `on delete cascade` — лайк живёт вместе с постом
([ADR-0007](../docs/adr/0007-hard-delete.md)).

Индекс по `user_id` не нужен: «все посты, которые я лайкнул» в MVP никто
не спрашивает, а по паре ключ уже есть.

Число лайков и признак «я отметил» считаются при чтении поста, тем же
запросом. Денормализованного счётчика в `posts` нет: он потребовал бы
согласованности при каждом лайке и удалении, а выигрыш на двух десятках
дачников — никакой.

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Лайк посту без лайков | `200`, `likes: 1`, `liked: true` |
| Лайк тому же посту второй раз | `200`, `likes` не растёт, `liked: true` |
| Снять свой лайк | `200`, `likes` уменьшается, `liked: false` |
| Снять лайк, которого не было | `200`, ничего не меняется, `liked: false` |
| Лайк своему посту | ставится: лента одна на всех |
| Лайк чужому посту | ставится |
| Два пользователя лайкнули один пост | `likes: 2`, у каждого `liked: true` |
| `liked` у того, кто не лайкал | `false`, даже если лайков много |
| Пост без лайков в ленте | `likes: 0`, `liked: false` |
| Лайк несуществующему посту | `404 post_not_found` |
| Идентификатор поста не похож на UUID | `404 post_not_found` |
| Снять лайк у несуществующего поста | `404 post_not_found` |
| Любой из запросов без токена | `401 unauthorized` |
| Лайки в ленте | приходят у каждого поста, `liked` — для того, кто спрашивает |
