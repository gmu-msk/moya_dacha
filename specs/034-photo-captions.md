# Спецификация: подпись к каждому фото

## Статус
В работе

## Зачем (контекст)
На первом тесте дачник выложил серию снимков отдельными постами подряд,
а не одной каруселью. Половина причины — экран создания поста не говорил,
что фото можно выбрать несколько ([#125](https://github.com/gmu-msk/moya_dacha/issues/125),
[003-posts](003-posts.md), требование 16). Вторая половина — к каждому
снимку хотелось написать своё: «это сорт Чудо», «а это та же грядка через
месяц». У поста была только одна подпись на всех.

Теперь у каждой фотографии поста может быть своя подпись автора
([#126](https://github.com/gmu-msk/moya_dacha/issues/126)). Общая подпись
поста остаётся как была. Это подпись автора, а не разговор: комментарии
к отдельному фото — вне рамок (решение Матвея 2026-10-15).

## Пользовательский сценарий

**Дано:** пользователь вошёл, на экране «Новый пост» выбраны три фото.

1. Касается второго превью — открывается окно «Подпись к фото 2», пишет
   «Сорт Чудо, третий год» и сохраняет. На превью появляется значок
   подписи.
2. Пишет общую подпись поста и публикует.
3. В ленте и на экране поста под каруселью — подпись первого фото
   (её нет — ничего), листает ко второму — «Сорт Чудо, третий год».
   Общая подпись поста ниже, как раньше.
4. Через «Изменить подпись» автор правит и общую подпись, и подписи фото,
   в одном окне.

**Тогда:** каждое фото несёт свой текст, а пост остаётся одним постом.

## Функциональные требования

### Подпись фото
1. У фотографии поста может быть подпись — текст до 1000 символов, как
   у подписи поста: края обрезаются, длина считается после обрезки,
   переводы строк разрешены ([003-posts](003-posts.md), требование 4).
   Пустая после обрезки — подписи нет.
2. Подпись фото принадлежит фото поста и живёт вместе с ним: удаление
   поста уносит и подписи ([007-deletion](007-deletion.md)).
3. У `Media` во всех ответах, где отдаются фотографии поста (лента,
   посты в профиле, группы, `GET /posts/{id}`, ответы на создание и
   правку), есть необязательное поле `caption`. Нет подписи — поля нет.
   Поле необязательное нарочно: сборка приложения без этой фичи читает
   ответ как раньше.
4. Подпись фото видна всем, кому виден пост (013).

### При создании поста
5. `POST /api/posts` принимает необязательное поле `media_captions` —
   объект «идентификатор фото → подпись». Ключ, которого нет
   в `media_ids`, — `400 invalid_media`. Фото, которого нет в объекте,
   публикуется без подписи. Нет поля, `null` или `{}` — все без подписей,
   как раньше.
6. Подпись фото длиннее 1000 символов после обрезки — `400 invalid_caption`,
   как у подписи поста.
7. Порядок проверок: число фото, подпись поста, подписи фото (длина),
   потом сами фото — и тогда же ключи `media_captions`
   ([003-posts](003-posts.md), «Проверки идут в этом порядке»).

### При правке
8. `PUT /api/posts/{postId}/caption` принимает необязательное поле
   `media_captions` в том же виде. Подписи перечисленных фото заменяются
   (пустая — подпись снята), остальных — не меняются. Нет поля —
   подписи фото не трогаются: так правит сборка без этой фичи.
9. Ключ, который не фото этого поста, — `400 invalid_media`. Подпись
   длиннее 1000 — `400 invalid_caption`. Эти проверки идут после
   «своё ли» ([022-edit-block-delete](022-edit-block-delete.md), требование 6):
   подпись поста, потом подписи фото, потом ключи.
10. `edited_at` ставится, если поменялся хоть один текст — подпись поста
    или любая подпись фото. Правка, после которой все тексты прежние,
    `edited_at` не трогает (022, требование 4).

### Тэги
11. Хэштеги в подписях фото — тоже тэги поста
    ([ADR-0029](../docs/adr/0029-tags-are-hashtags-in-caption.md)):
    тэги собираются из подписи поста, затем из подписей фото по порядку
    фото, по тем же правилам ([028-post-tags](028-post-tags.md),
    требования 3–5) — повторы схлопываются, первые 10 разных. Правка
    подписей пересчитывает тэги целиком (028, требование 6).

### В приложении
12. На экране «Новый пост» касание превью выбранного фото открывает окно
    «Подпись к фото N» с полем до 1000 символов. У фото с подписью на
    превью значок подписи. Крестик на превью по-прежнему убирает фото —
    вместе с его подписью.
13. Когда фото больше одного, строка под лентой превью (003, требование
    16) продолжается подсказкой «Коснитесь фото, чтобы подписать его».
14. В ленте и на экране поста подпись текущего фото — сразу под
    каруселью; листаешь — подпись меняется. Нет подписи у текущего фото —
    места под неё нет, общая подпись поста как раньше.
15. «Изменить подпись» у своего поста — одно окно: общая подпись сверху,
    ниже по полю на каждое фото с миниатюрой. Отправляются все поля
    разом. У поста из одного фото без подписи фото поле фото не
    показывается: хватает подписи поста.

## Вне рамок (Out of scope)
- Комментарии к отдельному фото (обсуждение конкретного снимка другими).
- Отметки людей и мест на фото.
- Подпись к фото без общей подписи поста как отдельный вид поста —
  это всё тот же пост.
- Поиск по подписям фото (поиск — [#78](https://github.com/gmu-msk/moya_dacha/issues/78)).

## API / контракт данных

Контракт целиком — в [specs/openapi.yaml](openapi.yaml).

```
POST /api/posts
Request: { "media_ids": [...], "caption": "...",
           "media_captions": { "<media_id>": "Сорт Чудо" }, ... }
Response 201: Post, у его media[i] — caption, если подпись есть

PUT /api/posts/{postId}/caption
Request: { "caption": "...", "media_captions": { "<media_id>": "" } }
Response 200: Post
```

Новых кодов ошибок нет: `invalid_media`, `invalid_caption` — те же, что
у создания поста.

## Модель данных

```
media.caption  text NULL   -- NULL — подписи нет; пустой строки не бывает
```

Подпись — колонка фото, а не отдельная таблица и не комментарий:
у фото одна подпись автора, и живёт она ровно столько, сколько фото
([ADR-0031](../docs/adr/0031-photo-caption-on-the-media.md)).

## Ограничения и edge cases

| Ситуация | Результат |
|---|---|
| Пост из трёх фото, подпись у второго | `201`, у `media[1].caption` — подпись, у остальных поля нет |
| `media_captions` с ключом не из `media_ids` | `400 invalid_media` |
| Подпись фото в 1001 символ | `400 invalid_caption` |
| Подпись фото из одних пробелов | фото без подписи |
| Без `media_captions` | как раньше, у фото подписей нет |
| Правка с `media_captions: {"<id>": ""}` | подпись этого фото снята, `edited_at` есть |
| Правка без `media_captions`, с `null` или `{}` | подписи фото прежние |
| Правка снимает подпись, которой не было | тексты прежние: `edited_at` не меняется |
| Ключ не UUID | `400 invalid_media`, как неизвестное фото |
| Длинная подпись под чужим ключом | `400 invalid_caption`: длина проверяется раньше ключей |
| Правка с ключом — фото другого поста | `400 invalid_media` |
| Правка, где все тексты прежние | `200`, `edited_at` не меняется |
| `#груша` в подписи фото | у поста тэг «груша» |
| Удаление поста | подписи фото уходят вместе с ним |

## Критерии готовности (Definition of Done)

- [ ] Подписи фото сохраняются при создании и правке, отдаются в `Media.caption`
- [ ] Хэштеги подписей фото становятся тэгами поста
- [ ] В приложении подпись фото задаётся касанием превью и видна под каруселью
- [ ] Есть сценарий показа `demo/stories/034-photo-captions/`, и
      `make story STORY=034-photo-captions` показывает фичу в эмуляторе
      ([ADR-0009](../docs/adr/0009-demo-story-per-feature.md))
- [ ] Экраны фичи проверены в тёмной теме и при максимальном системном
      размере шрифта ([ADR-0012](../docs/adr/0012-theme-and-shared-widgets.md))
