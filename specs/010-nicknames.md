# Спецификация: никнейм

## Статус
Готово

## Зачем (контекст)
Имя из [002-profile](002-profile.md) неуникально, и это было осознанно:
второй Николай никому не мешал, пока дачников было несколько. Но в ленте
и под комментариями два Николая с одинаковыми аватарками неразличимы,
а ни упомянуть человека, ни найти его потом по одному имени нельзя.

Поэтому у каждого пользователя есть никнейм — короткое уникальное имя
латиницей. Везде, где пользователя подписывают, показывается никнейм.
Полное имя остаётся, но становится необязательным: оно видно на странице
профиля под никнеймом.

## Пользовательский сценарий

**Дано:** пользователь только что вошёл впервые.

1. Приложение показывает экран знакомства: «Придумайте никнейм», ниже
   необязательные «Полное имя» и «О себе».
2. Пользователь вводит никнейм. Если такой уже занят (в том числе в другом
   регистре), под полем появляется «Этот никнейм уже занят» — пользователь
   меняет его и сохраняет снова.
3. После сохранения пользователь попадает в ленту.

**Тогда:** в ленте, на экране поста и у комментариев он подписан
никнеймом. На его странице крупно никнейм, а под ним полное имя, если он
его указал.

**Если пользователь зарегистрировался до появления никнеймов** — сервис
уже выдал ему временный никнейм вида `dachnik_3f9a01bc27`, и соседи видят
его. При следующем открытии приложения он попадает на тот же экран
знакомства с уже заполненными именем и «о себе» и выбирает свой никнейм.

**Позже** никнейм можно сменить на экране «Изменить профиль».

## Функциональные требования

1. У каждого пользователя есть никнейм, всегда: с момента, как пользователь
   заведён, и у тех, кто был заведён раньше этой фичи.
2. Никнейм — от 3 до 20 символов из латинских букв, цифр и знака
   подчёркивания `_`. Пробелы по краям обрезаются, всё остальное —
   `400 invalid_nickname`.
3. Никнейм уникален без учёта регистра: если есть `Valya`, то `valya`
   и `VALYA` заняты. Хранится и показывается он так, как его ввели.
4. Пока пользователь не выбрал никнейм сам, у него временный:
   `dachnik_` и десять случайных шестнадцатеричных цифр. Он подчиняется
   тем же правилам и так же уникален.
5. Сервис сообщает владельцу, выбран ли никнейм им самим
   (`nickname_chosen`). Пока не выбран, приложение показывает экран
   знакомства — это заменяет прежний признак «имя пустое».
6. Пользователь выбирает или меняет никнейм отдельной операцией. Занятый
   другим пользователем никнейм — `409 nickname_taken`. Свой же никнейм,
   в том числе в другом регистре, — не ошибка: он сохраняется в новом
   написании. После любой успешной смены никнейм считается выбранным.
7. Полное имя (поле `name` из [002-profile](002-profile.md)) становится
   необязательным: от 0 до 50 символов, одна строка. Пустое имя больше
   не означает, что пользователь не знакомился.
8. В публичном представлении автора и в профиле для соседей есть никнейм.
9. В приложении автор поста и комментария подписан никнеймом. На странице
   пользователя — никнейм крупно, ниже полное имя, если оно не пустое;
   в заголовке прокрутки его постов — никнейм. Буква на месте аватара —
   первая буква никнейма.
10. На экране «Изменить профиль» можно сменить никнейм, полное имя
    и «о себе».

## Вне рамок (Out of scope)

- Упоминания `@никнейм` в подписях и комментариях, поиск людей по никнейму.
- Проверка «свободен ли никнейм» по мере набора: занятость видна при
  сохранении.
- Запрет выбирать никнейм, похожий на временный (`dachnik_…`), список
  зарезервированных слов, фильтр неприличного.
- Ограничение на частоту смены никнейма и история прежних никнеймов.
- Кириллица в никнейме.

## API / контракт данных

Контракт целиком — в [specs/openapi.yaml](openapi.yaml).

### `PUT /api/me/nickname` — выбрать или сменить никнейм

```
Authorization: Bearer <токен>
Request:  { "nickname": "Valya_dacha" }
Response 200: профиль целиком, как у GET /api/me, с "nickname_chosen": true
Response 400: { "code": "invalid_nickname", "message": "..." }
Response 400: { "code": "invalid_request",  "message": "..." }
Response 401: { "code": "unauthorized",     "message": "..." }
Response 409: { "code": "nickname_taken",   "message": "..." }
```

### Что добавляется в ответы

`CurrentUser` (`GET /api/me`, `GET /api/auth/session`, ответ входа
и все операции профиля):

```
"nickname": "Valya_dacha",
"nickname_chosen": true
```

`Author` (рядом с постом и комментарием) и `UserProfile`
(`GET /api/users/{id}`): `"nickname": "Valya_dacha"`.

### `PUT /api/me` — изменить полное имя и «о себе»

Как в [002-profile](002-profile.md), только имя теперь может быть пустым:
`invalid_name` — это длиннее 50 символов или не одна строка. Никнейм этой
операцией не меняется.

### Ошибки

| код | статус | когда |
|---|---|---|
| `invalid_nickname` | 400 | нет никнейма, он короче 3 или длиннее 20 символов, или в нём есть символ кроме латиницы, цифр и `_` |
| `invalid_request` | 400 | тело запроса не разбирается или `nickname` в нём не строка |
| `nickname_taken` | 409 | такой никнейм без учёта регистра уже у другого пользователя |
| `unauthorized` | 401 | нет токена или он недействителен |

## Модель данных

```
users
  ...
  nickname        text NOT NULL        -- по умолчанию временный dachnik_<10 hex>
  nickname_chosen boolean NOT NULL DEFAULT false
  UNIQUE (lower(nickname))
```

Временный никнейм выдаёт сама база значением по умолчанию: так он есть
у каждой строки — и у новой, и у тех, что были до миграции.

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Новый пользователь после входа | `nickname` вида `dachnik_` + 10 шестнадцатеричных цифр, `nickname_chosen: false` |
| Два новых пользователя | временные никнеймы разные |
| Никнейм `Valya_dacha` | `200`, `nickname: "Valya_dacha"`, `nickname_chosen: true` |
| Никнейм с пробелами по краям | пробелы обрезаются |
| Ровно 3 и ровно 20 символов | принимается |
| 2 символа или 21 символ | `400 invalid_nickname` |
| Кириллица, пробел внутри, дефис, точка, `@` | `400 invalid_nickname` |
| Пустой никнейм или из одних пробелов | `400 invalid_nickname` |
| Нет поля `nickname` или оно `null` | `400 invalid_nickname`: то же, что пустой никнейм |
| `nickname` не строка (число, список, объект), тело не JSON | `400 invalid_request` |
| `valya` при чужом `Valya` | `409 nickname_taken`, никнейм не меняется |
| Свой же никнейм в другом регистре | `200`, сохраняется новое написание |
| Свой же никнейм без изменений | `200`, `nickname_chosen: true` |
| Смена никнейма | прежний освобождается и доступен другим |
| Чужой временный никнейм | `409 nickname_taken` |
| Никнейм в ленте, у комментария, в профиле соседа | новый сразу после смены |
| Полное имя пустое в `PUT /api/me` | `200`, имя очищается |
| Запрос без токена | `401 unauthorized` |

Что видит человек:

| где | текст |
|---|---|
| заголовок экрана знакомства | «Придумайте никнейм» |
| подсказка под полем никнейма | «Латиница, цифры и _, от 3 до 20 символов» |
| ошибка: неверный никнейм | «Никнейм — от 3 до 20 символов: латиница, цифры и _» |
| ошибка: занят | «Этот никнейм уже занят» |
