# Спецификация: обновление приложения поверх и «Что нового»

## Статус
В работе

## Зачем (контекст)
Тестировщики ставят APK по ссылке `/app.apk`. Сейчас каждая сборка
подписана debug-ключом своего раннера CI, а номер версии у всех один
(`1.0.0+1`). Поэтому новая сборка поверх старой не встаёт: Android видит
чужую подпись и просит удалить приложение, а с ним и вход.

Нужно, чтобы следующая сборка ставилась поверх предыдущей, человек видел,
что в ней поменялось, и узнавал о новой версии сам, а не из переписки.

Задача: [#41](https://github.com/gmu-msk/moya_dacha/issues/41).

## Пользовательский сценарий

**Дано:** у дачника стоит сборка 1.0.0 (сборка 390000), а на сервере уже
лежит сборка 390120.

1. Дачник открывает приложение. Сверху ленты появляется полоса
   «Вышла новая версия» с кнопкой «Скачать».
2. Кнопка открывает `/app.apk` в браузере телефона, APK скачивается.
3. Дачник ставит его поверх, ничего не удаляя. Вход сохраняется.
4. При первом запуске новой сборки открывается окно «Что нового» со списком
   изменений и кнопкой «Понятно». Второй раз оно не показывается.
5. В «Изменить профиль» внизу есть «О приложении»: версия, номер сборки,
   дата, коммит и тот же список «Что нового».

## Функциональные требования

1. Все сборки для телефона (из main и из PR) подписываются одним
   постоянным ключом. Где он хранится, решает
   [ADR-0021](../docs/adr/0021-one-signing-key.md).
2. Номер сборки (`versionCode`) растёт с каждой сборкой, в том числе между
   сборкой из PR и сборкой из main: это число минут от 2026-01-01 UTC на
   момент сборки. Номер прогона CI не годится: у каждого workflow он свой,
   и сборка main оказалась бы «старше» сборки PR и не встала бы поверх.
3. Версия (`versionName`) — из `pubspec.yaml`, как и раньше.
4. Сборка несёт в себе сведения о себе: версию, номер сборки, дату и время
   сборки, короткий коммит и список «Что нового» (до 10 строк).
   - Сборка main: заголовки PR, вошедших в main со сборки, которая сейчас
     лежит на сервере. Если прошлую сборку узнать нельзя — заголовок
     последнего PR.
   - Сборка PR: одна строка — заголовок этого PR.
5. Вместе с APK на сервер кладётся `/app.json` — сведения о сборке из
   пункта 4 в том же виде.
6. При каждом запуске приложение запрашивает `/app.json` у сервера, на
   который смотрит сборка по умолчанию (зашитый адрес, не выбранный на
   экране «Сервер»: APK лежит на проде). Если номер сборки там больше
   своего — показывает полосу «Вышла новая версия» с кнопкой «Скачать»
   и крестиком «Не сейчас». Крестик прячет полосу до следующего запуска.
7. Окно «Что нового» показывается один раз после входа в приложение, если
   номер сборки отличается от последнего показанного и список не пуст.
8. «О приложении» открывается из экрана «Изменить профиль».

## Вне рамок (Out of scope)
- Обновление внутри приложения без браузера и установка по кнопке.
- Google Play и его механизм обновлений.
- «Что нового» человеческими словами: пока это заголовки PR как есть.
- Принудительное обновление (старые сборки продолжают работать).

## API / контракт данных
Ручек в `specs/openapi.yaml` не добавляется: `/app.json` — статический файл
рядом с `/app.apk`, его отдаёт Caddy.

```
GET /app.json
200: {
  "version": "1.0.0",
  "build": 390120,
  "date": "2026-09-26T12:00:00Z",
  "commit": "aa652ef",
  "whatsNew": ["Заголовок PR", "..."]
}
```

Тот же файл лежит в APK как `assets/build_info.json`. В репозитории он
заглушка с `build: 0`: сборка на машине разработчика и в эмуляторе
на CI себя сборкой не считает и обновлений не ищет.

## Модель данных
Нет. На устройстве хранится только номер сборки, для которой уже показано
окно «Что нового».

## Ограничения и edge cases
- `/app.json` не отвечает, отвечает не JSON или без номера — полосы нет,
  ошибка не показывается: это не то, ради чего человек открыл приложение.
- Своя сборка `build: 0` (разработка, эмулятор) — проверки нет, окна нет.
- Номер на сервере меньше или равен своему (например, стоит сборка из PR
  новее main) — полосы нет.
- Первая установка с постоянным ключом: прошлую сборку, подписанную
  debug-ключом, придётся один раз удалить. Об этом говорит
  «Как понять, что готово» в задаче.

Тексты:
- полоса: «Вышла новая версия», кнопки «Скачать» и «Не сейчас»;
- окно: заголовок «Что нового», кнопка «Понятно»;
- «О приложении»: подписи «Версия», «Сборка», «Собрано», «Коммит»,
  раздел «Что нового»; у сборки без сведений — «Сборка для разработки».

## Критерии готовности (Definition of Done)

- [ ] Сборка из PR ставится поверх сборки из main и наоборот
- [ ] Новая сборка из main ставится поверх старой, вход сохраняется
- [ ] После обновления один раз показывается «Что нового»
- [ ] Старая сборка при запуске предлагает скачать новую
- [ ] В «О приложении» видны версия, номер сборки, дата и коммит
- [ ] Есть сценарий показа `demo/stories/017-app-updates/`, и
      `make story STORY=017-app-updates` показывает фичу в эмуляторе
      ([ADR-0009](../docs/adr/0009-demo-story-per-feature.md))
- [ ] Экраны фичи проверены в тёмной теме и при максимальном системном
      размере шрифта ([ADR-0012](../docs/adr/0012-theme-and-shared-widgets.md))
