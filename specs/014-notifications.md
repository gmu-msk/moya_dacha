# Спецификация: уведомления

## Статус
Черновик

## Зачем (контекст)
С подписками ([012-follows](012-follows.md)) появились события, о которых
человек должен узнать: на него подписались, к нему пришла заявка, его
заявку приняли. Лайки ([005-likes](005-likes.md)) и комментарии
([006-comments](006-comments.md)) до сих пор можно заметить, только
открыв свой пост. Раздел «Уведомления» собирает всё это в одном месте.

Push-уведомлений в MVP нет ([000-overview](000-overview.md)): раздел
внутри приложения, о новом говорит точка на значке в нижней панели.

Решение Матвея в треде «Подписки» 2026-09-24: раздел в нижней панели
сразу, в нём подписки, заявки, лайки и комментарии.

## Пользовательский сценарий

**Дано:** пользователь вошёл и знаком.

1. В нижней панели четвёртый значок — колокольчик, между «Новым постом»
   и «Профилем». Когда есть непрочитанное, на нём маковая точка.
2. Пользователь касается колокольчика — открывается «Уведомления».
   Сверху «Заявки на подписку» (если профиль закрыт и они есть), у каждой
   «Принять» и «Отклонить». Ниже — события, новые сверху: «Новое» и
   «Раньше».
3. Строка события: аватар, ник, что случилось, сколько времени назад,
   справа — миниатюра поста или кнопка «Подписаться».
4. Касание строки с постом открывает пост, строки с человеком — его
   профиль.
5. Точка на колокольчике гаснет, как только раздел открыт.

**Тогда:** человек узнаёт, что его посты смотрят и обсуждают, и не
пропускает заявки.

## Функциональные требования

1. События:
   - `follow` — «<ник> подписался на вас»; справа «Подписаться», если
     смотрящий ещё не подписан на него, иначе «Вы подписаны»;
   - `follow_accepted` — «<ник> принял вашу заявку»;
   - `like` — «<ник> отметил ваш пост»; несколько лайков одного поста
     сливаются в одну строку «<ник> и ещё N отметили ваш пост», с
     последним отметившим и временем последнего лайка;
   - `comment` — «<ник> ответил на ваш пост: «<начало комментария>»».
   Заявки — не события: они отдельным списком сверху
   ([012-follows](012-follows.md), `GET /api/me/follow-requests`).
2. Автор поста теперь узнаёт, кто его отметил: это меняет требование 5
   из [005-likes](005-likes.md). Под самим постом списка отметивших
   по-прежнему нет, и остальные его не видят.
3. Свои действия уведомлений не порождают: лайк своему посту, коммент
   под своим постом.
4. Событие исчезает, если причина отменена: лайк снят (из слитой строки
   уходит этот человек), комментарий удалён, подписчик отписался, пост
   удалён ([007-deletion](007-deletion.md)).
5. Непрочитанные — события новее момента, когда человек последний раз
   открыл раздел, плюс ждущие заявки. Точка на колокольчике горит,
   пока есть хоть одно непрочитанное.
6. Приложение узнаёт о новом без опроса сервиса: при запуске, при
   каждом переключении раздела в нижней панели и при обновлении ленты
   (потянуть вниз). Фонового опроса нет, как и в ленте
   ([004-feed](004-feed.md)).
7. Раздел делит события на «Новое» (непрочитанные на момент открытия)
   и «Раньше». Открытие раздела отмечает всё прочитанным.
8. События отдаются страницами по курсору, новые сверху; хранятся
   последние 90 дней.
### Вид

9. Нижняя панель — четыре раздела: Лента, Новый пост, Уведомления,
   Профиль ([011-bottom-bar](011-bottom-bar.md)). Колокольчик в том же
   рисунке: контуром, открытый — залит на подложке. Точка — маковый
   кружок в правом верхнем углу значка с каймой цвета полотна.
10. Имя в строке — ник васильком, время — приглушённым после текста.
    Миниатюра поста — квадрат 48 со скруглением 8. «Принять» — залитая
    маковая, «Отклонить» — с контуром, обе под текстом заявки.

## Вне рамок (Out of scope)

- Push-уведомления и уведомления на почту или в СМС.
- Уведомления о постах тех, на кого подписан («у Коли новый пост»).
- Настройки: какие события получать.
- Упоминания через `@ник` и ответы на комментарии.

## API / контракт данных

Контракт дописывается в [specs/openapi.yaml](openapi.yaml) при
реализации, до кода.

### `GET /api/me/notifications` — события страницами

```
Параметры: limit (1..50, по умолчанию 20), cursor
Response 200: {
  "items": [ {
    "id": "…",
    "kind": "follow" | "follow_accepted" | "like" | "comment",
    "created_at": "…",
    "actor": Author + "relation": Relation,   — последний, кто это сделал
    "others": 3,                              — только у like: сколько ещё
    "post": { "id": "…", "thumbnail": Media }, — у like и comment
    "comment": "Какие огурцы! Сорт какой?",   — у comment, до 100 символов
    "unread": true
  } ],
  "next_cursor": "…"
}
```

### `GET /api/me/notifications/unread` — есть ли новое

```
Response 200: { "unread": 4, "requests": 1 }
```

### `PUT /api/me/notifications/seen` — отметить всё прочитанным

```
Response 204
```

## Модель данных

```sql
CREATE TABLE notifications (
    id          uuid        PRIMARY KEY,
    user_id     uuid        NOT NULL REFERENCES users (id) ON DELETE CASCADE, -- кому
    kind        text        NOT NULL CHECK (kind IN ('follow','follow_accepted','like','comment')),
    actor_id    uuid        NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    post_id     uuid        REFERENCES posts (id) ON DELETE CASCADE,
    comment_id  uuid        REFERENCES comments (id) ON DELETE CASCADE,
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX notifications_user_idx ON notifications (user_id, created_at DESC, id DESC);

ALTER TABLE users ADD COLUMN notifications_seen_at timestamptz NOT NULL DEFAULT now();
```

Каждое действие — своя строка; лайки одного поста сливаются при чтении
(группировка по `post_id` для `kind = 'like'`). Отмена действия удаляет
строку; каскады убирают события удалённых постов и комментариев.
Строки старше 90 дней удаляются при чтении списка, как неопубликованные
медиа удаляются при следующей загрузке ([003-posts](003-posts.md)):
фонового уборщика в сервисе нет.

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Три лайка одному посту | одна строка: последний отметивший «и ещё 2» |
| Лайк снят | человек уходит из строки; если он был один — строки нет |
| Лайк своему посту | события нет |
| Комментарий удалён | строки нет |
| Пост удалён | все его события пропали |
| Подписался и сразу отписался | строки нет |
| Заявка принята | у заявителя событие `follow_accepted`, у хозяина — ничего |
| Открыл профиль, заявки приняты сами | у каждого заявителя `follow_accepted` |
| Событий нет | пустое состояние |
| Событие старше 90 дней | его нет |

**Тексты.** Пустой раздел: «Здесь появятся отметки, комментарии и новые
подписчики». Заголовки секций: «Заявки на подписку», «Новое», «Раньше».

## Критерии готовности (Definition of Done)

- [ ] Колокольчик в нижней панели с точкой непрочитанного
- [ ] Раздел с заявками сверху и событиями четырёх видов
- [ ] Лайки одного поста сливаются в одну строку
- [ ] Отменённое действие убирает событие
- [ ] Демо-данные: у демо-пользователя есть непрочитанные события всех
      видов и заявка
- [ ] Есть сценарий показа `demo/stories/014-notifications/`, и
      `make story STORY=014-notifications` показывает фичу в эмуляторе
      ([ADR-0009](../docs/adr/0009-demo-story-per-feature.md))
- [ ] Экраны фичи проверены в тёмной теме и при максимальном системном
      размере шрифта ([ADR-0012](../docs/adr/0012-theme-and-shared-widgets.md))
