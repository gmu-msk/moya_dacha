# Спецификация: Telegram-бот — сборки, тревоги, /статус

## Статус
В работе

## Зачем (контекст)
Владелец узнаёт о тревогах из задач GitHub раз в два часа, а о новых
сборках из комментариев в PR. Тестировщики вообще не знают, что вышла
новая версия, пока им не скажут. Telegram у всех есть, и пуш из него
приходит сразу.

Задача: [#42](https://github.com/gmu-msk/moya_dacha/issues/42). Решение
о каналах — [ADR-0022](../docs/adr/0022-telegram-bot-inside-the-service.md).

## Пользовательский сценарий

**Дано:** владелец создал бота у @BotFather и положил токен в секрет
репозитория `TELEGRAM_BOT_TOKEN`, свой ник Telegram — в переменную
`TELEGRAM_OWNER`. Прошёл деплой из main.

1. Владелец пишет боту в личку `/start`. Бот отвечает, что личка
   привязана: сюда пойдут тревоги и тестовые сборки.
2. Владелец добавляет бота в группу тестировщиков и пишет там `/group`.
   Бот отвечает, что группа привязана: сюда пойдут сборки приложения.
3. PR слит в main. После деплоя в группу приходит APK файлом с подписью
   «МояДача 1.0.0, сборка 386900» и списком «Что нового».
4. В PR запушен коммит. Владельцу в личку приходит сообщение о тестовой
   сборке со ссылкой на APK из релиза PR.
5. На сервере кончается диск. Через минуту владельцу в личку приходит
   «Тревога на проде» со списком тревог. Когда место освободили, приходит
   «Всё в порядке: тревог больше нет».
6. Владелец пишет `/status` (или `/статус`). Бот отвечает сводкой: тревоги,
   люди и посты, ошибки за сутки, машина.

## Функциональные требования

### Настройка
1. Бот — часть сервиса, пакет `backend/internal/telegram`, отдельного
   процесса нет. Сервис запускает его, только если задана переменная
   `TELEGRAM_BOT_TOKEN`; без неё бота нет, остальное работает как раньше.
2. Владелец задаётся ником Telegram в `TELEGRAM_OWNER` (без `@`, регистр
   не важен). Ник, а не номер чата: номер владелец не знает, а ник знает.
3. Деплой переносит секрет `TELEGRAM_BOT_TOKEN` и переменную
   `TELEGRAM_OWNER` репозитория в `/etc/moya-dacha.env`. Пустое значение
   строку не трогает.

### Привязка чатов
4. Чатов у бота два: **личка владельца** (`owner`) и **группа** (`group`).
   Номера хранятся в таблице `telegram_chats`, по одной строке на роль;
   новая привязка роли заменяет старую.
5. `/start` в личке от владельца привязывает личку. Ответ:
   «Готово: сюда будут приходить тревоги и тестовые сборки.»
6. `/group` или `/группа` в группе или супергруппе от владельца привязывает
   группу. Ответ: «Готово: сюда будут приходить сборки приложения.»
7. Любая команда в личке от кого-то, кроме владельца, получает ответ
   «Это служебный бот МоейДачи.» и ничего не меняет. В группе команды
   не от владельца бот молча пропускает: иначе он отвечал бы на каждое
   сообщение тестировщиков.
8. Команда — первое слово сообщения. Часть после `@` (`/status@moya_bot`)
   и регистр не важны. Сообщения без `/` в начале бот пропускает.

### /статус
9. `/status` или `/статус` от владельца, в личке или в группе, получает
   сводку. Строки по порядку:
   - «Всё в порядке» — или «Тревоги:» и под ней по строке «• <текст
     тревоги>» на каждую тревогу дашборда (specs/016-dashboard.md);
   - «Людей: N, постов: M»;
   - «Ошибок за сутки: K»;
   - «Процессор X%, память A из B, диск C из D» — если есть хоть одно
     измерение машины; размеры — как на дашборде («1,4 ГБ»);
   - «Работает: …» — сколько работает процесс сервиса.

### Тревоги
10. Раз в минуту сервис считает тревоги дашборда (те же, что команда
    `alerts`). Когда набор видов тревог (`disk`, `errors`, `memory`)
    изменился и в нём что-то есть, владельцу в личку уходит:

        Тревога на проде:
        • <текст тревоги>
        • …

    Список — все текущие тревоги, а не только новые.
11. Когда набор стал пустым после непустого, уходит «Всё в порядке:
    тревог больше нет.»
12. Набор не изменился — ничего не уходит: тексты тревог меняются
    (свободное место на диске), а пуш каждую минуту об одном и том же
    не нужен.
13. Помнит бот только последний отправленный набор и только в памяти.
    После перезапуска сервиса текущие тревоги приходят ещё раз.
14. Личка не привязана — ничего не уходит, и отправленным набор не
    считается: после привязки тревога придёт на следующей проверке.
15. Сторож остаётся в GitHub Actions (прогон «Дашборд», ADR-0019): если
    лёг весь сервер, бот ничего не пришлёт, а задача «алерт» появится.

### Сборки
16. Команда `moya-dacha-server build-notify <owner|group> <сведения> [<apk>|<ссылка>]`
    отправляет сборку в чат роли. `<сведения>` — путь к JSON сведений о
    сборке (specs/017-app-updates.md) или `-` для стандартного ввода.
    Третий аргумент — путь к APK (уходит файлом) или ссылка `https://…`
    (уходит текстом). Без третьего — только текст.
17. Подпись:

        МояДача 1.0.0, сборка 386900
        Что нового:
        • <строка>
        • …

    Со ссылкой ниже через пустую строку — «Скачать: <ссылка>». Файл
    называется `moya-dacha-<сборка>.apk`.
18. Бот не настроен (нет токена) или чат роли не привязан — команда
    печатает, почему сборка не ушла, и выходит с кодом 0: деплой из-за
    этого не красный. Telegram ответил ошибкой — код 1.
19. Деплой из main после выкладки APK отправляет его в группу. Сборка PR
    уходит владельцу ссылкой на релиз PR; неудача этого шага CI не
    роняет.

### Как это видно из Go (для тестов)
20. `telegram.New(db *pgxpool.Pool, cfg telegram.Config) *telegram.Bot`,
    где `Config` — `Token`, `APIURL` (по умолчанию
    `https://api.telegram.org`), `Owner`, `DiskPath` (где мерить диск для
    тревог и сводки) и `PollTimeout` (long polling, по умолчанию 50 с).
21. `(*Bot).Run(ctx)` — читает обновления `getUpdates`, пока не отменён
    `ctx`, и отвечает на команды. `(*Bot).CheckAlerts(ctx) error` — одна
    проверка тревог из требований 10–14. `(*Bot).SendBuild(ctx, role
    string, info []byte, apk string, link string) error` — отправка
    сборки из требований 16–17; не привязанный чат —
    `telegram.ErrNotBound`.
22. С Telegram бот говорит методами Bot API по адресу
    `<APIURL>/bot<Token>/<метод>`: `getUpdates` и `sendMessage` — JSON в
    теле POST, `sendDocument` — multipart с полями `chat_id`, `caption`
    и файлом `document`. Ответ Telegram `{"ok": false}` — ошибка.

## Вне рамок (Out of scope)
- Обратная связь через бота и задачи «входящее» — отдельная задача этапа.
- Рассылка тестировщикам в личку: только группа.
- Webhook вместо long polling: сервис за Caddy один, опрос проще.
- Команды для тестировщиков. Бот отвечает только владельцу.
- Разметка сообщений (Markdown/HTML): текст как есть.

## API / контракт данных
Ручек в `specs/openapi.yaml` не добавляется: бот ходит в Telegram сам.

## Модель данных

```
telegram_chats
  role      text        PRIMARY KEY, 'owner' или 'group'
  chat_id   bigint      NOT NULL
  bound_at  timestamptz NOT NULL DEFAULT now()
```

## Ограничения и edge cases
- Telegram недоступен — бот пишет в лог и повторяет опрос через 5 секунд;
  сервис из-за этого не падает.
- Бот удалили из группы — отправка в группу вернёт ошибку, её видно в
  логе прогона деплоя. Привязать заново — `/group` в новой группе.
- Файл больше 50 МБ Telegram не примет. Release-APK меньше, сборка PR
  (debug) больше — поэтому она уходит ссылкой.
- Команды на кириллице Telegram не подсвечивает как команды, но текстом
  они приходят, и бот их понимает. В меню бота — латинские `/status`,
  `/group`.

Тексты:
- «Готово: сюда будут приходить тревоги и тестовые сборки.»
- «Готово: сюда будут приходить сборки приложения.»
- «Это служебный бот МоейДачи.»
- «Тревога на проде:», «Всё в порядке: тревог больше нет.»
- `build-notify`: «Бот не настроен: сборка не отправлена», «Чат <роль>
  не привязан: сборка не отправлена».

## Критерии готовности (Definition of Done)

- [ ] `/start` от владельца привязывает личку, от другого — нет
- [ ] `/group` от владельца в группе привязывает группу
- [ ] `/status` отвечает сводкой владельцу и только ему
- [ ] Тревога приходит в личку за минуту, «всё в порядке» — когда прошла,
      повторов нет
- [ ] После мерджа APK сам приходит в группу со «Что нового»
- [ ] Сборка PR приходит владельцу ссылкой
- [ ] Есть сценарий показа `demo/stories/018-telegram-bot/`
      ([ADR-0009](../docs/adr/0009-demo-story-per-feature.md))
