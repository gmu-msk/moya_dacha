# Спецификация: лента

## Статус
Готово

## Зачем (контекст)
Пост уже можно опубликовать ([003-posts](003-posts.md)), но увидеть его
может только тот, кто его создал, и только сразу после публикации. Лента —
то место, ради которого приложение открывают не чтобы выложить, а чтобы
посмотреть. Без неё проверить гипотезу проекта нельзя: постить некому и
не для кого ([000-overview](000-overview.md)).

Лента одна на всех: все посты всех пользователей, новые сверху. Подписок,
друзей и сообществ нет — это осознанное решение масштаба закрытого теста
([CONTEXT.md](../CONTEXT.md)).

## Пользовательский сценарий

**Дано:** пользователь вошёл и знаком (у него есть имя).

1. Пользователь открывает приложение и сразу видит ленту: сверху самый
   свежий пост, ниже те, что старше.
2. Прокручивает вниз — по мере прокрутки подгружаются следующие посты.
3. Тянет ленту вниз — она обновляется: появляется то, что выложили,
   пока он смотрел.
4. Нажимает на пост — открывается сам пост со всеми фотографиями и
   подписью целиком ([003-posts](003-posts.md)).
5. Публикует свой пост — и видит его первым в ленте.

**Тогда:** дачник видит, что выросло у соседей, не прося у них ссылку.

**Если постов ещё нет** — лента говорит, что здесь пока пусто, и
предлагает выложить первый.

## Функциональные требования

1. Лента — все посты всех пользователей в обратном хронологическом
   порядке: новые сверху. Своих постов лента не прячет и чужих не
   выделяет ([CONTEXT.md](../CONTEXT.md)).
2. Лента отдаётся страницами: сервис возвращает посты и курсор на
   продолжение. Курсор — непрозрачная строка: клиент её не разбирает
   и не строит сам, а возвращает как получил
   ([ADR-0015](../docs/adr/0015-feed-paginated-by-cursor.md)).
3. Курсор указывает на место в порядке ленты, а не на номер страницы.
   Посты, выложенные между запросами страниц, не сдвигают и не
   задваивают то, что человек уже пролистал. Курсор не привязан
   к пользователю: лента одна на всех, и тот же курсор от другого
   вошедшего даёт ту же страницу.
4. Размер страницы задаёт клиент, от 1 до 50 постов; по умолчанию 20.
   Больше пятидесяти за раз не отдаётся: на дачной связи это разница
   между «лента поехала» и «приложение думает».
5. Пост в ленте приходит в том же виде, что и по своему адресу: автор,
   подпись, фотографии с размерами и временем публикации. Отдельного
   усечённого представления нет — одна фича, один способ показать пост
   ([003-posts](003-posts.md)).
6. Последняя страница — та, у которой нет курсора на продолжение: курсор
   выдаётся, только когда за отданной страницей есть ещё хотя бы один
   пост. Пустая лента отдаётся пустым списком без курсора.
7. Ленту видит любой вошедший пользователь. Без токена ленты нет: сервис
   закрыт целиком ([001-auth](001-auth.md)).
8. Опубликованный пост появляется в ленте сразу: отложенной публикации
   и очередей в проекте нет.
9. В ленте у поста показывается первая фотография, а если их больше —
   отметка вида «1/4». Остальные видно на экране поста. Так лента
   тянет по одной фотографии на пост, а не по четыре
   ([ADR-0006](../docs/adr/0006-post-is-media.md)).
10. Место под фотографию занимается до того, как она загрузится: размеры
    приходят вместе с постом, и лента не дёргается при прокрутке
    ([003-posts](003-posts.md), требование 8).
11. Длинная подпись в ленте показывается не целиком: первые строки и
    дальше пост открывается целиком. Лента — это витрина, а не чтение.
12. Обновление ленты (потянуть вниз) запрашивает первую страницу заново
    и показывает её вместо накопленного: так человек видит свежее, а не
    склейку из двух моментов времени.
13. Ошибка загрузки следующей страницы не стирает уже показанное: лента
    остаётся на экране, под ней — сообщение и «Повторить».

## Вне рамок (Out of scope)

- **Лайки** ([005](000-overview.md)) и **комментарии**
  ([006](000-overview.md)): их счётчики появятся в посте вместе с ними,
  и ленте для этого хватит нового поля в ответе.
- **Удаление поста** ([007-deletion](000-overview.md)): пока пост из
  ленты не исчезает.
- **Жалобы** ([008](000-overview.md)).
- Лента конкретного пользователя (посты одного автора) — её нет в MVP:
  подписок и профилей других людей не существует.
- Поиск, фильтры, теги, рекомендации: порядок ленты — только время.
- Прокрутка фотографий поста прямо в ленте: за этим — экран поста.
- Обновление ленты само по себе, без участия человека: ни опроса
  сервиса, ни push-уведомлений в MVP нет
  ([000-overview](000-overview.md)).
- Кеш ленты на устройстве: пустая лента без связи — это честно,
  а хранилище постов на клиенте пришлось бы согласовывать с удалением.

## API / контракт данных

Контракт целиком — в [specs/openapi.yaml](openapi.yaml).

### `GET /api/feed` — страница ленты

```
Authorization: Bearer <токен>
Параметры запроса:
  limit  — сколько постов вернуть, 1..50, по умолчанию 20
  cursor — курсор из предыдущего ответа; без него отдаётся первая страница

Response 200: {
  "items": [ пост целиком, как у GET /api/posts/{id} ],
  "next_cursor": "MjAyNi0wOS0yMFQxMDowMDowMFp8N2Y0…"
}
Response 400: { "code": "invalid_request", "message": "..." }
Response 400: { "code": "invalid_cursor",  "message": "..." }
Response 401: { "code": "unauthorized",    "message": "..." }
```

`next_cursor` есть только тогда, когда за этой страницей есть ещё хотя бы
один пост. Его отсутствие — единственный признак конца ленты; в ответе
тогда нет самого поля (не `null`: контракт его пустым не описывает).

Пустой `items` при этом встречается ровно в двух случаях: лента пуста
вовсе и за курсором не осталось постов — так бывает, если пост, до
которого дочитали, исчез. Полная страница всегда идёт с курсором, поэтому
«листать до пустой страницы» не нужно: конец виден сразу.

Курсор непрозрачен для клиента, но не секретен: внутри — время
публикации и идентификатор последнего отданного поста. Он не заменяет
токен и ничего не открывает: без токена ответа не будет.

### Ошибки

| код | статус | когда |
|---|---|---|
| `invalid_request` | 400 | `limit` не число, пустой, указан дважды, меньше 1 или больше 50 |
| `invalid_cursor` | 400 | курсор не разбирается: испорчен или из другой версии |
| `unauthorized` | 401 | нет токена или он недействителен |

## Модель данных

Новых таблиц и колонок не нужно: лента читает `posts` и `media`
([003-posts](003-posts.md)). Порядок и страницы обеспечивает уже
существующий индекс:

```
posts_created_at_idx on posts (created_at desc, id desc)
```

Страница берётся не смещением, а от места:

```sql
SELECT … FROM posts
WHERE ($1::timestamptz IS NULL)
   OR (created_at, id) < ($1, $2)
ORDER BY created_at DESC, id DESC
LIMIT $3
```

Пара `(created_at, id)` строго убывает и уникальна, поэтому пост не
пропускается и не повторяется, даже если в ту же миллисекунду
опубликовано несколько постов. `OFFSET` для этого не годится: он
считает от начала, и каждый новый пост сдвигает всё, что ниже
([ADR-0015](../docs/adr/0015-feed-paginated-by-cursor.md)).

Медиа для страницы читаются одним запросом на всю страницу, а не по
запросу на пост: двадцать постов — это два запроса к базе, а не
двадцать один.

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Постов нет ни у кого | `200`, `items: []`, курсора нет |
| Постов меньше, чем `limit` | все посты одной страницей, курсора нет |
| Постов ровно `limit` | страница отдаётся; курсора нет, если дальше пусто |
| Постов больше, чем `limit` | страница и курсор на продолжение |
| Запрос без `limit` | 20 постов |
| `limit=` пустой или указан дважды | `400 invalid_request`: запрос не разбирается |
| `limit=1` | один пост и курсор |
| `limit=50` | до пятидесяти постов |
| `limit=51`, `limit=0`, `limit=-1`, `limit=abc` | `400 invalid_request` |
| Курсор из предыдущего ответа | посты строго старше последнего отданного |
| Курсор, за которым не осталось постов | `200`, `items: []`, курсора нет |
| Испорченный или чужеродный курсор | `400 invalid_cursor` |
| Пустой `cursor=` | как будто курсора нет: первая страница |
| Курсор поста, который больше не существует | страница от того же места: курсор — это время и идентификатор, а не ссылка на строку |
| Новый пост между запросами страниц | во второй странице не появляется и ничего не сдвигает |
| Два поста с одинаковым `created_at` | порядок устойчив: по идентификатору, тоже по убыванию |
| Свои посты | в ленте наравне с чужими |
| Пост с четырьмя фотографиями | в `items` приходит целиком, все четыре |
| Пост без подписи | приходит с пустой подписью |
| Автор без аватара | `avatar_url` отсутствует |
| Запрос без токена или с неизвестным токеном | `401 unauthorized` |
| Курсор, выданный другому вошедшему | работает: лента одна на всех |

Две строки этой таблицы сервис сам создать не может: одинаковое
`created_at` он не проставляет, а удаления постов до
[007-deletion](000-overview.md) нет вовсе. Тесты готовят такое состояние
прямо в базе — это единственное место, где им позволено ходить мимо HTTP
([ADR-0002](../docs/adr/0002-tests-as-the-only-gate.md)).
