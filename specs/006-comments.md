# Спецификация: комментарии

## Статус
Готово

## Зачем (контекст)
Лайк ([005-likes](005-likes.md)) говорит «увидел и понравилось», но
разговора из него не выходит. А разговор — это то, ради чего дачники
и собираются: «чем брызгали?», «у нас такая же напасть», «дай пару
корешков осенью». Гипотеза проекта проверяется именно этим: люди не
только выкладывают своё, но и отвечают друг другу
([000-overview](000-overview.md)).

Комментарий — текст, оставленный пользователем под постом. Комментарии
плоские: ответов на комментарий не существует, и лайков у комментариев
нет. Комментарий живёт только вместе со своим постом
([CONTEXT.md](../CONTEXT.md)).

## Пользовательский сценарий

**Дано:** пользователь вошёл и смотрит пост.

1. Под постом он видит, сколько там комментариев, и сами комментарии —
   от первого к последнему, как разговор.
2. Пишет свой и отправляет.
3. Комментарий появляется последним, с его именем и временем.
4. В ленте у поста видно число комментариев: понятно, где разговор идёт,
   а где ещё нет. Пока комментариев нет, стоит один значок без числа
   (specs/000-ui.md, правило 15).

**Тогда:** автор поста получает ответ, а не только число сердечек.

**Если связь пропала** — написанное не теряется: оно остаётся в поле,
и человек видит, что отправить не удалось.

## Функциональные требования

1. Вошедший пользователь оставляет комментарий под любым постом, включая
   свой: лента одна на всех, и запрет комментировать себя ничего не
   бережёт ([005-likes](005-likes.md), требование 2 — тот же довод).
2. Комментарий — это текст и ничего больше: ни фотографий, ни ответов
   на другой комментарий, ни лайков ([CONTEXT.md](../CONTEXT.md)).
3. Текст обязателен. Пустой комментарий и комментарий из одних пробелов
   не принимаются: под постом нечего показывать. Края текста
   обрезаются, как у подписи поста ([003-posts](003-posts.md),
   требование 5): обрезаются любые пробельные символы, переводы строк
   в том числе, — и длина считается после обрезки.
4. Длина — не больше 1000 символов, как у подписи поста: та же мера
   в тех же единицах, чтобы человеку не приходилось помнить две.
   Символ — кодовая точка Unicode, а не байт и не то, что человек
   видит одним знаком: эмодзи из нескольких кодовых точек считается
   несколькими.
5. Комментарии читаются от старого к новому: это разговор, и читается
   он сверху вниз. При одинаковом времени порядок по идентификатору,
   тоже по возрастанию, — иначе одинаковые сотые доли секунды дают
   разный порядок при каждом чтении ([004-feed](004-feed.md),
   требование 3 — там по той же причине, но в обратную сторону).
   Идентификаторы сравниваются так, как их сравнивает база: порядок
   значений типа `uuid`.
6. Комментарии поста приходят целиком, без страниц
   ([ADR-0016](../docs/adr/0016-comments-come-whole.md)). Два десятка
   дачников не напишут под постом столько, чтобы это стоило курсора:
   страницы ленты нужны потому, что лента растёт вечно, а разговор под
   постом — нет. Если это перестанет быть правдой, тот же курсор, что
   у ленты, добавляется не ломая ответ.
7. У поста есть число комментариев, и оно приходит везде, где приходит
   пост: в ленте, на самом посте, в ответе на публикацию и в ответах
   на лайк и его снятие — у свежего поста это `0`
   ([005-likes](005-likes.md), требование 4 — так же, как `likes`).
   В ответе на новый комментарий поста нет вовсе: там приходит
   комментарий ([ADR-0016](../docs/adr/0016-comments-come-whole.md)),
   и число приложение берёт из следующего чтения поста.
8. Число комментариев считается по факту, отдельного счётчика в посте
   нет — по тем же причинам, что и у лайков
   ([005-likes](005-likes.md), требование 7).
9. Комментарий правится только своим автором и только по адресу своего
   поста — это [022-edit-block-delete](022-edit-block-delete.md),
   требование 3. Других адресов правки нет, поэтому любой другой запрос
   на правку — ошибка; какая именно, спецификация не оговаривает: это не
   поведение фичи, а отсутствие адреса. Удаление своего комментария — следующая
   фича ([007-deletion](000-overview.md)), и до неё написанное
   остаётся.
10. Комментарий живёт вместе с постом: удаление поста уносит и
    комментарии ([ADR-0007](../docs/adr/0007-hard-delete.md)).
11. У комментария виден автор — имя и аватар, как у поста
    ([002-profile](002-profile.md)). Номер телефона не виден нигде
    ([CONTEXT.md](../CONTEXT.md)).
12. Комментарии видны любому вошедшему; без токена их нет, как и всего
    остального ([001-auth](001-auth.md)).
13. В приложении отправленный комментарий появляется в списке сразу
    после ответа сервиса, и поле очищается. Если сервис ответил
    ошибкой — текст остаётся в поле и человек видит, что не получилось:
    заставлять набирать заново на дачной связи нельзя.

## Вне рамок (Out of scope)

- **Ответы на комментарии**: комментарии плоские
  ([CONTEXT.md](../CONTEXT.md)).
- **Лайки комментариев**: их нет вовсе.
- Редактирование комментария: это
  [022-edit-block-delete](022-edit-block-delete.md).
- Удаление комментария: это [007-deletion](000-overview.md).
- Жалоба на комментарий: это [008-reports](000-overview.md).
- Фотографии в комментарии, упоминания, теги и ссылки: комментарий —
  просто текст, как и подпись ([003-posts](003-posts.md)).
- Уведомление автору поста о комментарии: push-уведомлений в MVP нет
  ([000-overview](000-overview.md)).
- Страницы комментариев: требование 6.

## API / контракт данных

Контракт целиком — в [specs/openapi.yaml](openapi.yaml).

### `GET /api/posts/{postId}/comments` — комментарии поста

```
Authorization: Bearer <токен>

Response 200: { "items": [ комментарий, … ] }
Response 401: { "code": "unauthorized",   "message": "..." }
Response 404: { "code": "post_not_found", "message": "..." }
```

Комментарии — от старого к новому. У поста без комментариев `items`
пустой, и это не ошибка: поле есть всегда.

### `POST /api/posts/{postId}/comments` — оставить комментарий

```
Authorization: Bearer <токен>
Content-Type: application/json

{ "text": "И у нас такая же напасть, брызгали содой" }

Response 201: комментарий целиком
Response 400: { "code": "empty_comment",   "message": "..." }
Response 400: { "code": "invalid_comment", "message": "..." }
Response 401: { "code": "unauthorized",    "message": "..." }
Response 404: { "code": "post_not_found",  "message": "..." }
```

Ответ — созданный комментарий, а не пост целиком: у поста комментарии
приходят отдельным запросом, и класть их в ответ означало бы отдавать
весь разговор на каждую реплику.

Проверки идут в этом порядке: сначала токен, потом пост, потом текст.
Поэтому комментарий без токена к несуществующему посту — это `401`,
а пустой комментарий к несуществующему посту — `404`: сервис сначала
отвечает, есть ли куда писать ([005-likes](005-likes.md), тот же
порядок).

### Комментарий

```
{
  "id": "uuid",
  "created_at": "2026-09-21T10:00:00Z",
  "text": "И у нас такая же напасть, брызгали содой",
  "author": { "id": "uuid", "name": "Николай", "avatar_url": "/media/…" }
}
```

Автор — то же представление, что у поста ([003-posts](003-posts.md)):
имя и аватар, без номера телефона.

### Пост в ответе

К посту добавилось одно поле, и оно приходит везде, где приходит пост:

```
{
  …
  "likes": 3,
  "liked": true,
  "comments": 2
}
```

`comments` — сколько комментариев под постом. Поле обязательное: пост
без комментариев приходит с `"comments": 0`, а не без поля.

### Ошибки

| код | статус | когда |
|---|---|---|
| `empty_comment` | 400 | текста нет, он пустой или из одних пробелов |
| `invalid_comment` | 400 | текст длиннее 1000 символов |
| `invalid_request` | 400 | тело запроса не разбирается, пустое или `text` в нём не строка |
| `unauthorized` | 401 | нет токена или он недействителен |
| `post_not_found` | 404 | поста с таким идентификатором нет |

## Модель данных

```
comments
  id         uuid        primary key default gen_random_uuid()
  post_id    uuid        not null references posts(id) on delete cascade
  author_id  uuid        not null references users(id)
  text       text        not null
  created_at timestamptz not null default now()

index comments_post_id_idx (post_id, created_at, id)
```

`on delete cascade` — комментарий живёт вместе с постом
([ADR-0007](../docs/adr/0007-hard-delete.md)). Индекс по
`(post_id, created_at, id)` — это и есть единственный порядок чтения:
комментарии одного поста от старого к новому.

Число комментариев считается при чтении поста, тем же запросом, что и
лайки. Денормализованного счётчика в `posts` нет
([005-likes](005-likes.md), «Модель данных»).

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Комментарий к посту без комментариев | `201`, у поста `comments: 1` |
| Второй комментарий того же человека | `201`: сколько угодно реплик, это разговор |
| Комментарий к своему посту | оставляется: лента одна на всех |
| Порядок комментариев | от старого к новому, при равном времени — по идентификатору |
| Пост без комментариев | `200`, `items: []` |
| Текст из одних пробелов и переводов строки | `400 empty_comment` |
| Пустая строка в `text` | `400 empty_comment` |
| `text` отсутствует в теле | `400 empty_comment`: запрос понятен, текста в нём нет |
| Пробелы по краям текста | обрезаются, сохраняется обрезанный |
| Переводы строки внутри текста | сохраняются как есть |
| Ровно 1000 символов после обрезки | `201` |
| 1001 символ после обрезки | `400 invalid_comment` |
| Длина считается в символах | эмодзи и буквы с диакритикой — один символ, не байт |
| Тело запроса не JSON | `400 invalid_request` |
| Пустое тело запроса | `400 invalid_request`: пустая строка — не JSON |
| `text` не строка (например число) | `400 invalid_request`: запрос не разбирается, а не «текста нет» |
| Комментарий к несуществующему посту | `404 post_not_found` |
| Идентификатор поста не похож на UUID | `404 post_not_found` |
| Чтение комментариев несуществующего поста | `404 post_not_found` |
| Любой из запросов без токена | `401 unauthorized` |
| Запрос без токена к несуществующему посту | `401 unauthorized`: токен проверяется первым |
| Пустой комментарий к несуществующему посту | `404 post_not_found`: пост проверяется раньше текста |
| Число комментариев в ленте | приходит у каждого поста |
| Комментарий чужого человека | виден всем: лента одна на всех |

Требование 8 (счётчика в таблице нет) и требование 13 (текст остаётся
в поле при ошибке) по HTTP не проверяются: первое — про то, как считает
сервис, второе — про приложение. Первое видно в коде и в миграции,
второе смотрит человек по сценарию показа
([ADR-0009](../docs/adr/0009-demo-story-per-feature.md)).
