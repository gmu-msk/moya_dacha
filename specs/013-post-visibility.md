# Спецификация: видимость постов

## Статус
В работе

## Зачем (контекст)
Закрытый профиль ([012-follows](012-follows.md)) решает, кто видит дачу
целиком. Но и у открытого профиля бывает пост не для всех: урожай для
своих, фото участка, которое хочется показать только близким, или пост
«для себя» — заметка, куда что посажено. Поэтому видимость выбирается
у каждого поста.

Решение Матвея в треде «Подписки» 2026-09-24: у каждого поста три уровня —
всем, друзьям, только мне; друзья — взаимная подписка. Видимость можно
поменять и у опубликованного поста.

## Пользовательский сценарий

**Дано:** пользователь вошёл и знаком.

1. На экране «Новый пост» под подписью — выбор «Кто увидит»: «Всем»,
   «Друзьям», «Только мне». Выбрано «Всем».
2. Пользователь выбирает «Друзьям» и публикует. В ленте у поста рядом со
   временем отметка «друзьям».
3. Друг видит пост в ленте, может отметить и прокомментировать. Тот,
   кто подписан на автора, но без взаимности, поста не видит вовсе.
4. Автор открывает свой пост, в заголовке касается значка видимости
   («Кто увидит») и меняет на
   «Только мне». Пост пропадает у всех, кроме автора, но не удаляется.

**Тогда:** человек сам решает про каждый пост, кому его показать.

## Функциональные требования

1. У поста одна из трёх видимостей: `all` — «Всем», `friends` —
   «Друзьям», `me` — «Только мне». По умолчанию `all`.
2. Кто видит пост автора A (смотрящий V):
   - V — это A: всегда;
   - `me`: никто, кроме A;
   - `friends`: V и A подписаны друг на друга ([012-follows](012-follows.md),
     требование 5);
   - `all` у открытого профиля: все;
   - `all` у закрытого профиля: подписчики A.
3. У закрытого профиля пункт «Всем» на экране выбора подписан
   «Подписчикам»: значение то же, `all`, но слово честнее.
4. Видимость проверяется везде, где пост может попасть к человеку:
   обе вкладки ленты, посты пользователя, пост по адресу, лайки,
   комментарии, жалобы, уведомления ([014-notifications](014-notifications.md)).
   Для того, кому пост не виден, его нет: `404 post_not_found`, как у
   несуществующего, — чтобы не выдавать, что пост есть.
5. Видимость считается в момент запроса. Перестали быть друзьями — пост
   «друзьям» пропадает у бывшего друга сразу; стали — появляется. Автор
   закрыл профиль — посты «Всем» пропадают у не-подписчиков.
6. Автор меняет видимость своего поста в любой момент из меню поста.
   Лайки и комментарии при этом остаются; кто перестал видеть пост, их
   тоже не видит.
7. Отметка на карточке: у `friends` — значок двух человечков и слово
   «друзьям», у `me` — замок и «только мне», рядом со временем
   публикации. У `all` отметки нет.
8. Выбор «Кто увидит» — три строки со значком, названием, пояснением и
   кружком выбора; выбранная — на подложке. Пояснения: «Все дачники в
   МоейДаче» (у закрытого: «Только ваши подписчики»), «Те, с кем вы
   подписаны друг на друга», «Пост виден только вам».

## Вне рамок (Out of scope)

- Списки «близкие друзья» и видимость для выбранных людей.
- Видимость отдельной фотографии поста.
- Правка подписи и фотографий: по-прежнему только удаление
  ([007-deletion](007-deletion.md)).
- Закрытие файлов фотографий: файл отдаётся по ссылке со случайным
  именем ([ADR-0011](../docs/adr/0011-files-behind-storage-interface.md)).
  Кто однажды получил ссылку, откроет её и после смены видимости. Для
  закрытого теста на двадцать человек это приемлемо; настоящая защита —
  отдельной фичей вместе с переездом на S3.

## API / контракт данных

Контракт дописывается в [specs/openapi.yaml](openapi.yaml) при
реализации, до кода.

- `PostDraft` получает необязательное `visibility`: `all` | `friends` |
  `me`; без него — `all`. Другое значение — `400 invalid_request`.
- `Post` получает обязательное `visibility`.

### `PUT /api/posts/{postId}/visibility` — сменить видимость

```
Request:  { "visibility": "friends" }
Response 200: Post
Response 400: { "code": "invalid_request" }
Response 403: { "code": "not_your_post" }
Response 404: { "code": "post_not_found" }
```

Чужой пост, который смотрящему виден, — `403 not_your_post`; невидимый —
`404 post_not_found`.

## Модель данных

```sql
ALTER TABLE posts ADD COLUMN visibility text NOT NULL DEFAULT 'all'
    CHECK (visibility IN ('all', 'friends', 'me'));
```

Одно условие видимости на все запросы постов, в SQL, а не в Go после
выборки: иначе страница ленты придёт короче `limit` и курсор собьётся.

```sql
p.author_id = $viewer
OR (p.visibility = 'all' AND (NOT a.closed OR EXISTS
      (SELECT 1 FROM follows WHERE follower_id = $viewer
         AND followee_id = p.author_id AND accepted)))
OR (p.visibility = 'friends' AND EXISTS (…я → он, accepted…)
                            AND EXISTS (…он → я, accepted…))
```

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Пост без `visibility` | `all` |
| `visibility: "public"` | `400 invalid_request`, пост не создан |
| Пост «друзьям», смотрит друг | виден везде, можно лайкать и комментировать |
| Пост «друзьям», смотрит подписчик без взаимности | `404 post_not_found`, в лентах нет |
| Пост «только мне» | виден только автору, в том числе в его «Подписках» |
| Друг отписался | дружбы нет: посты «друзьям» пропадают у обоих — и его у автора, и автора у него |
| Автор сменил `all` на `me` | пост пропал у всех, лайки и комментарии на месте |
| Смена видимости чужого видимого поста | `403 not_your_post` |
| Лайк или комментарий к невидимому посту | `404 post_not_found` |
| Жалоба на невидимый пост | `404 post_not_found` |
| Закрытый профиль, пост «Всем» | видят только подписчики |
| Число постов в профиле | только видимые смотрящему ([012-follows](012-follows.md), требование 13) |

**Тексты.** Заголовок выбора — «Кто увидит». Пункт меню поста — «Кто
увидит»; после смены — короткое сообщение «Теперь пост видят: друзья»
(«все», «подписчики», «только вы»).
