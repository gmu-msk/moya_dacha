# Спецификация: профиль пользователя для соседей

## Статус
В работе

## Зачем (контекст)
В ленте ([004-feed](004-feed.md)) у каждого поста есть автор, но узнать
о нём больше нельзя: имя и аватар ведут в никуда. Дачники знакомы друг
с другом, и первое, что хочется сделать, увидев чужую теплицу, — посмотреть,
что ещё у этого человека растёт.

Профиль — экран, на котором пользователя показывают
([CONTEXT.md](../CONTEXT.md)): кто он и все его посты. Устроен он как в
Инстаграме: посты сеткой, касание фотографии открывает посты этого
человека подряд, и их можно листать, не возвращаясь к сетке.

Свой профиль — тот же экран: человек видит себя так, как его видят соседи.
Правка имени, «о себе» и аватара из [002-profile](002-profile.md) остаётся
как есть и открывается из своего профиля кнопкой.

## Пользовательский сценарий

**Дано:** пользователь вошёл и знаком (у него есть имя).

1. В ленте пользователь касается имени или аватара автора поста —
   открывается профиль автора. То же на экране поста и у комментария.
2. Сверху — аватар, имя, сколько у человека постов, с какого времени он
   в МоейДаче и «о себе».
3. Ниже — все его посты сеткой по три, новые сверху: в каждой клетке
   первая фотография поста. Сетка подгружается по мере прокрутки.
4. Пользователь касается клетки — открываются посты этого человека
   карточками, как в ленте, сразу на том посте, которого коснулся.
   Листать можно в обе стороны: вверх — к более новым, вниз — к более
   старым, до самого первого поста.
5. В карточке можно отметить пост и перейти к комментариям; касание
   карточки открывает пост целиком ([003-posts](003-posts.md)).
6. Аватар в шапке ленты открывает свой профиль. В нём есть кнопка
   «Изменить профиль» — она ведёт на экран правки профиля с номером
   телефона и «Выйти» ([002-profile](002-profile.md)).

**Тогда:** по любому посту в ленте можно узнать, чей он, и посмотреть
всё, что этот человек выкладывал.

**Если у человека нет постов** — профиль показывает, кто это, и говорит,
что постов пока нет.

## Функциональные требования

1. Профиль пользователя виден любому вошедшему: имя, «о себе», аватар,
   дата регистрации и число постов. Без токена профиля нет: сервис закрыт
   целиком ([001-auth](001-auth.md)).
2. Номер телефона в профиль не входит и входить не может — ни в чужой,
   ни в свой ([CONTEXT.md](../CONTEXT.md)). Свой номер человек видит
   только на экране правки профиля, который отдаёт `GET /api/me`.
3. Число постов — сколько постов у человека сейчас: удалённый пост
   ([007-deletion](007-deletion.md)) из него уходит сразу.
4. Посты пользователя отдаются страницами по курсору, как лента
   ([ADR-0015](../docs/adr/0015-feed-paginated-by-cursor.md)): только его
   посты, новые сверху, в том же виде, что и в ленте
   ([004-feed](004-feed.md), требование 5). Размер страницы — от 1 до 50,
   по умолчанию 20; последняя страница — без курсора.
5. Курсор постов пользователя — это место в порядке постов, а не номер
   страницы: новые посты человека между запросами страниц ничего не
   сдвигают и не задваивают. Курсор ленты и курсор постов пользователя
   устроены одинаково.
6. Профиль и посты открываются по идентификатору пользователя — тому
   самому `author.id`, что приходит с постом и комментарием.
7. Пользователь, которого нет, — `404 user_not_found`. Так же отвечает
   идентификатор, который не является UUID: для клиента это одно и то же.
8. Свой профиль отдаётся той же ручкой, что и чужой, и выглядит так же.
   Отличие одно — кнопка «Изменить профиль» в приложении.
9. В приложении имя и аватар автора открывают его профиль в ленте, на
   экране поста и у комментария.
10. Посты в профиле показываются сеткой по три квадрата: первая
    фотография поста, обрезанная по центру. Если фотографий в посте
    больше одной, в углу клетки значок «несколько фотографий».
11. Касание клетки открывает посты этого человека карточками ленты
    сразу на выбранном посте. Выше него — более новые посты, ниже —
    более старые; следующие страницы подгружаются по мере прокрутки
    вниз. Строки автора в карточке нет: автор один и назван в заголовке.
12. Лайк, поставленный в прокрутке или на экране поста, виден и в сетке,
    и в прокрутке, и в ленте, когда человек туда вернётся
    ([005-likes](005-likes.md)).
13. Удалённый из профиля свой пост исчезает из сетки и прокрутки
    ([007-deletion](007-deletion.md), требование 7).
14. Потянуть профиль вниз — он перечитывается целиком: сведения о человеке
    и первая страница постов.
15. Ошибка следующей страницы не стирает уже показанное: под ним —
    сообщение и «Повторить», как в ленте ([004-feed](004-feed.md),
    требование 13).

## Вне рамок (Out of scope)

- Подписки, друзья и сообщества: лента по-прежнему одна на всех
  ([CONTEXT.md](../CONTEXT.md)).
- Поиск людей и список всех пользователей: в профиль попадают только
  через автора поста или комментария.
- Лайки и комментарии, которые человек поставил другим: в профиле только
  его посты.
- Правка профиля прямо на экране профиля: она остаётся на отдельном
  экране из [002-profile](002-profile.md).
- Жалоба на пользователя: жалуются на пост или комментарий
  ([008-reports](008-reports.md)).
- Закрытый профиль и скрытие постов от кого-то: все посты видны всем.
- Отдельная ручка «посты новее этого»: прокрутка открывается из сетки,
  а сетка всегда начинается с самого нового поста, поэтому всё, что
  выше выбранного, у приложения уже есть.

## API / контракт данных

Контракт целиком — в [specs/openapi.yaml](openapi.yaml).

### `GET /api/users/{userId}` — профиль пользователя

```
Authorization: Bearer <токен>
Response 200: {
  "id": "uuid",
  "name": "Валентина",
  "about": "Теплица, три грядки клубники и кот Василий",
  "avatar_url": "/media/avatars/6f1c….jpg",
  "created_at": "2026-05-14T10:00:00Z",
  "posts": 14
}
Response 401: { "code": "unauthorized",   "message": "..." }
Response 404: { "code": "user_not_found", "message": "..." }
```

`about` — пустая строка, если не задано; `avatar_url` отсутствует или
`null`, пока аватара нет. Поля `phone` нет.

### `GET /api/users/{userId}/posts` — посты пользователя страницами

```
Authorization: Bearer <токен>
Параметры запроса:
  limit  — сколько постов вернуть, 1..50, по умолчанию 20
  cursor — курсор из предыдущего ответа; без него отдаётся первая страница

Response 200: {
  "items": [ пост целиком, как у GET /api/posts/{id} ],
  "next_cursor": "MjAyNi0wOS0yMFQxMDowMDowMFp8N2Y0…"
}
Response 400: { "code": "invalid_request", "message": "..." }
Response 400: { "code": "invalid_cursor",  "message": "..." }
Response 401: { "code": "unauthorized",    "message": "..." }
Response 404: { "code": "user_not_found",  "message": "..." }
```

Ответ — та же схема `Feed`, что у ленты, и правила курсора те же
([004-feed](004-feed.md)): `next_cursor` есть, только когда дальше есть
хотя бы один пост.

### Ошибки

| код | статус | когда |
|---|---|---|
| `invalid_request` | 400 | `limit` не число, пустой, указан дважды, меньше 1 или больше 50 |
| `invalid_cursor` | 400 | курсор не разбирается |
| `unauthorized` | 401 | нет токена или он недействителен |
| `user_not_found` | 404 | пользователя нет или идентификатор не UUID |

## Модель данных

Новых таблиц и колонок не нужно: профиль читает `users`, посты — `posts`
и `media`. Для страниц одного автора нужен индекс, иначе каждая страница
профиля перебирает все посты всех авторов:

```
posts_author_created_at_idx on posts (author_id, created_at desc, id desc)
```

Страница берётся так же, как в ленте, с условием на автора:

```sql
SELECT … FROM posts
WHERE author_id = $1
  AND (($2::timestamptz IS NULL) OR (created_at, id) < ($2, $3))
ORDER BY created_at DESC, id DESC
LIMIT $4
```

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Профиль чужого пользователя | `200`: имя, «о себе», аватар, дата регистрации, число постов; поля `phone` нет |
| Свой профиль по своему идентификатору | `200`, то же самое, поля `phone` нет |
| Пользователь без аватара | `avatar_url` отсутствует или `null` |
| Пользователь без «о себе» | `about: ""` |
| Пользователь без постов | профиль с `posts: 0`; посты — `items: []`, курсора нет |
| Число постов после публикации нового | на один больше |
| Число постов после удаления поста | на один меньше |
| Неизвестный идентификатор (UUID, которого нет) | `404 user_not_found` и для профиля, и для постов |
| Идентификатор не UUID (`abc`) | `404 user_not_found` и для профиля, и для постов |
| Посты пользователя | только его, чужих в ответе нет |
| Порядок постов | новые сверху; при одинаковом `created_at` — по идентификатору, тоже по убыванию |
| Постов меньше, чем `limit` | все одной страницей, курсора нет |
| Постов ровно `limit` | страница без курсора |
| Постов больше, чем `limit` | страница и курсор на продолжение |
| Курсор из предыдущего ответа | посты этого же человека строго старше последнего отданного |
| Новый пост человека между запросами страниц | во второй странице не появляется и ничего не сдвигает |
| Запрос без `limit` | 20 постов |
| `limit=0`, `limit=51`, `limit=abc`, пустой или дважды | `400 invalid_request` |
| Испорченный курсор | `400 invalid_cursor` |
| Пустой `cursor=` | первая страница |
| Пост в ответе | целиком, как в ленте: автор, все фотографии, лайки, «я отметил», число комментариев |
| Любой запрос без токена или с неизвестным токеном | `401 unauthorized` |

Одинаковое `created_at` у двух постов сервис сам не проставляет: тесты
готовят такое состояние прямо в базе, как в ленте
([ADR-0002](../docs/adr/0002-tests-as-the-only-gate.md)).

### Что видит человек

| состояние | текст |
|---|---|
| Постов нет, чужой профиль | «Постов пока нет» и ниже «Когда <имя> что-нибудь выложит, это появится здесь и в ленте» |
| Постов нет, свой профиль | «Постов пока нет» и ниже «Выложите первый — он появится здесь и в ленте» |
| Число постов | «1 пост», «3 поста», «14 постов»; «постов пока нет», когда их нет |
| Дата регистрации | «в МоейДаче с мая», «в МоейДаче с мая 2025» для прошлых лет |
| Профиль не открылся | текст ошибки от сервиса и «Повторить» |
