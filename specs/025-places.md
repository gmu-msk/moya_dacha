# Спецификация: населённый пункт в профиле

## Статус
В работе

## Зачем (контекст)
Дачники ищут «своих»: соседей по СНТ, по деревне. Чтобы это было видно,
у человека в профиле появляется населённый пункт — СНТ, деревня, посёлок
и т. п. От этой привязки дальше отталкиваются геометка поста
([#75](https://github.com/gmu-msk/moya_dacha/issues/75)) и группы по СНТ
([#79](https://github.com/gmu-msk/moya_dacha/issues/79)).

Свободный текст не годится: люди из одного товарищества напишут название
по-разному, и сгруппировать их потом не получится. Поэтому значение
выбирается только из подсказок единого справочника адресов ФИАС (ГАР,
ведёт ФНС) и хранится с его постоянным идентификатором. Подсказки даёт
сервис DaData поверх ФИАС; сервер спрашивает его сам, ключ в приложение
не попадает.

Задача: [#99](https://github.com/gmu-msk/moya_dacha/issues/99), эпик
[#74](https://github.com/gmu-msk/moya_dacha/issues/74). Профиль —
[002-profile](002-profile.md), страница пользователя —
[009-user-profile](009-user-profile.md). Продолжение — подсказка по
геолокации, [#100](https://github.com/gmu-msk/moya_dacha/issues/100).

## Пользовательский сценарий

**Дано:** человек вошёл, на сервере задан ключ DaData.

1. Человек открывает свой профиль → «Изменить профиль». Под «О себе» —
   поле «Населённый пункт», пустое.
2. Он набирает «Андрейково». Под полем выпадает список: «снт Андрейково»
   с подписью «Дмитровский р-н, Московская обл», «д Андрейково» с
   подписью «Вологодский р-н, Вологодская обл» и т. д.
3. Он касается «снт Андрейково». Поле показывает выбранное: название
   и подпись под ним.
4. Он сохраняет профиль. В своём профиле и в профиле, который видят
   соседи, под «о себе» — «снт Андрейково» и мелко «Дмитровский р-н,
   Московская обл».
5. Сосед из того же СНТ выбирает тот же пункт — у обоих одна и та же
   запись (один идентификатор ФИАС).

## Функциональные требования

### Подсказки
1. `GET /api/places?q=<текст>` — подсказки населённых пунктов, только
   для вошедшего (`401` без токена). Ответ `200`:
   `{"places": [Place, …]}`, не больше 10, в порядке, в каком их дал
   справочник.
2. `q` обрезается по краям; короче 2 символов или длиннее 100 (символы,
   а не байты) — `400 invalid_query`, справочник не спрашивается. В
   справочник уходит обрезанный текст.
3. `Place` — `{"id", "name", "area"}`:
   - `id` — идентификатор объекта в ФИАС (строка);
   - `name` — название с типом ровно так, как его дал справочник
     («снт Андрейково», «д Андрейково», «г Дмитров»);
   - `area` — уточнение: что выше пункта, от ближнего к дальнему, через
     «, » («Дмитровский р-н, Московская обл»). Выше ничего нет (регион
     или город федерального значения) — пустая строка.
4. Ключа DaData нет, справочник не ответил за 5 секунд или ответил не
   `200`, ответ не разобрался — `503 places_unavailable`.
5. Каждый отданный пункт сервер запоминает у себя (таблица `places`):
   новый добавляется, у уже известного обновляются `name` и `area`.
   Выбрать в профиле можно только запомненный пункт (требование 9).

### Как сервер спрашивает DaData
6. Запрос — `POST <адрес>/suggest/address`, где `<адрес>` по умолчанию
   `https://suggestions.dadata.ru/suggestions/api/4_1/rs`. Заголовки
   `Authorization: Token <ключ>`, `Content-Type: application/json`,
   `Accept: application/json`. Тело: `{"query": "<q>", "count": 20}`.
7. Ответ — `{"suggestions": [{"value": "…", "data": {"fias_id": "…",
   "fias_level": "…", …}}, …]}`. Нет поля `suggestions` — подсказок нет (`200`, пустой список).
   Из подсказки берутся только `value`,
   `data.fias_id` и `data.fias_level`; остальные поля не нужны. Подсказка
   пропускается, если `fias_id` пуст или `fias_level` не один из `"4"`
   (город), `"6"` (населённый пункт), `"65"` (планировочная структура —
   так в ГАР записаны СНТ), `"90"` (дополнительная территория — так СНТ
   записаны в старом ФИАС). `fias_level` может прийти и числом.
8. `value` делится по «, »; части обрезаются по краям, пустые
   отбрасываются. `name` — последняя часть, `area` — остальные в обратном
   порядке через «, ». Пример: `"Московская обл, Дмитровский р-н, снт
   Андрейково"` → `name` «снт Андрейково», `area` «Дмитровский р-н,
   Московская обл». Повтор `fias_id` в одном ответе пропускается. В ответ
   идут первые 10 оставшихся.

### Выбор в профиле
9. `PUT /api/me/place` с телом `{"place_id": "<id>"}` ставит пункт,
   `{"place_id": null}`, пустая строка или тело без `place_id` — убирает. Ответ `200` —
   `CurrentUser`. `place_id`, которого сервер не запоминал по
   требованию 5, — `400 unknown_place`, профиль не меняется. Справочник
   при этом не спрашивается: ручка работает и без ключа DaData.
10. У человека один пункт: новый заменяет прежний.
11. В `CurrentUser` (`GET /me` и все ответы, что его отдают) и в
    `UserProfile` (`GET /users/{id}`) появляется поле `place` — `Place`;
    пункт не выбран — поля нет (или `null`, клиент понимает оба). Поле в контракте необязательное
    (сборка приложения из PR ходит на сервер с main).
12. Пункт виден всем, кто видит шапку профиля, — как имя и «о себе»
    (в том числе в закрытом профиле).
13. Удаление аккаунта (022) стирает и привязку; запись в `places`
    остаётся.

### Как это видно из Go (для тестов)
14. Адрес и ключ DaData — поля `api.Config`: `PlacesURL` (пусто —
    адрес по умолчанию из требования 6) и `PlacesKey` (пусто — подсказок
    нет, `503`). В сервисе — переменные окружения `DADATA_URL` и
    `DADATA_API_KEY`, на VPS ключ кладёт деплой из секрета репозитория
    `DADATA_API_KEY`.

### Приложение
15. На экране «Изменить профиль» под «О себе» — поле «Населённый пункт».
    Набор от 2 символов, после паузы 300 мс, запрашивает подсказки;
    список под полем: сверху `name`, под ним мелко `area` (пустой `area`
    — одна строка).
16. Касание подсказки выбирает пункт: поле показывает `name` и под ним
    `area`, рядом — кнопка «Убрать». Сохранить можно только выбранный
    из подсказок пункт: набранный и не выбранный текст не сохраняется.
17. Пункт сохраняется кнопкой «Сохранить» вместе с именем и «о себе»
    (`PUT /me/place` после `PUT /me`, только если пункт изменился).
18. Тексты: подсказок нет — «Ничего не нашлось»; `503` или нет сети —
    «Подсказки сейчас недоступны»; ошибка сохранения — как у остальных
    полей профиля.
19. В своём и чужом профиле (009) под «о себе» — `name` и под ним мелко
    `area`. Пункта нет — строки нет.

## Вне рамок (Out of scope)
- Подсказка по геолокации — [#100](https://github.com/gmu-msk/moya_dacha/issues/100).
- Несколько пунктов у одного человека.
- Пункт, которого нет в справочнике: добавить руками нельзя.
- Пункт в карточке поста рядом с ником; поиск людей по пункту.
- Выгрузка всего ФИАС к себе.

## API / контракт данных

```
GET /api/places?q=Андрейково          → 200 | 400 invalid_query | 401 | 503 places_unavailable
  {"places": [
    {"id": "5f4a…", "name": "снт Андрейково", "area": "Дмитровский р-н, Московская обл"},
    {"id": "0c1d…", "name": "д Андрейково",   "area": "Вологодский р-н, Вологодская обл"}]}

PUT /api/me/place                     → 200 CurrentUser | 400 unknown_place | 401
  {"place_id": "5f4a…"}  |  {"place_id": null}

CurrentUser, UserProfile: + "place": Place   (необязательное; нет пункта — нет поля)
```

## Модель данных

```
places                               -- пункты, которые сервер отдавал в подсказках
  id          text        PRIMARY KEY      -- идентификатор ФИАС
  name        text        NOT NULL
  area        text        NOT NULL DEFAULT ''
  updated_at  timestamptz NOT NULL

users
  + place_id  text        → places, может быть пусто
```

## Ограничения и edge cases
- Два одноимённых пункта — разные записи с разными `id`; различает их
  `area`, она видна и в подсказке, и в профиле.
- Справочник переименовал пункт — при следующей подсказке обновятся
  `name` и `area`, у всех, кто его выбрал.
- Сборка из PR на сервере с main: `/places` там нет (`404`), приложение
  пишет «Подсказки сейчас недоступны», остальной профиль работает.
