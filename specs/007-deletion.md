# Спецификация: удаление своего

## Статус
Готово

## Зачем (контекст)
Выложить можно не то и не тем: фотографию с чужим двором, подпись, о
которой наутро жалеешь, комментарий, написанный сгоряча. Пока убрать
это нельзя, человек осторожничает — а осторожничающий дачник ничего не
выкладывает, и проверять в проекте становится нечего
([000-overview](000-overview.md)).

Удаление в проекте жёсткое: сказано «удалено» — значит, из базы оно
ушло, и флага «удалён» в модели нет
([ADR-0007](../docs/adr/0007-hard-delete.md)). Поэтому и спрашивать
подтверждение обязательно: вернуть будет нечем.

Удалять можно только своё: свой пост и свой комментарий. Чужое убирает
владелец сервиса руками по жалобе — это следующая фича
([008-reports](000-overview.md)).

## Пользовательский сценарий

**Дано:** пользователь вошёл и смотрит свой пост.

1. У своего поста он видит «Удалить», у чужого — нет.
2. Нажимает и получает вопрос: удалить безвозвратно?
3. Подтверждает — пост исчезает, и приложение возвращает его в ленту,
   где поста уже нет.
4. Под чужим постом он так же удаляет свой комментарий, и число
   комментариев уменьшается.

**Тогда:** выложенное перестаёт быть окончательным, и выкладывать
становится не страшно.

**Если связь пропала** — ничего не удаляется, и человек видит, что не
получилось.

## Функциональные требования

1. Автор удаляет свой пост. Вместе с постом уходят его фотографии, его
   лайки и его комментарии — в том числе чужие: комментарий не
   существует отдельно от поста ([CONTEXT.md](../CONTEXT.md),
   [ADR-0007](../docs/adr/0007-hard-delete.md)).
2. Автор удаляет свой комментарий. Пост при этом не трогается, а его
   число комментариев уменьшается ([006-comments](006-comments.md),
   требование 7).
3. Чужой пост и чужой комментарий не удаляются — даже автором поста, под
   которым чужой комментарий оставлен. Убрать чужое можно только жалобой
   ([008-reports](000-overview.md)): решение о чужом принимает владелец
   сервиса, а не тот, кому оно не понравилось.
4. Удаление необратимо. Флага «удалён» нет: удалённое не лежит в базе
   ([ADR-0007](../docs/adr/0007-hard-delete.md)).
5. Файлы удалённых фотографий убираются из хранилища. Если хранилище не
   отозвалось, пост всё равно удалён: человеку сказано «удалено», и
   откатывать это из-за неубранного файла нельзя — осиротевший файл
   попадает в лог ([ADR-0011](../docs/adr/0011-files-behind-storage-interface.md)).
   Пока хранилище — локальный диск, файл перестаёт отдаваться в том же
   запросе, а не когда-нибудь потом
   ([ADR-0007](../docs/adr/0007-hard-delete.md), уточнение): ждать
   нечего, и проверять «исчезнет ли» ожиданием не нужно.
6. Удалить то, чего уже нет, — ошибка, а не «и так всё в порядке»:
   повторное удаление отвечает `404`. Лайк идемпотентен потому, что
   важен итог ([005-likes](005-likes.md), требование 3); здесь же
   второй запрос означает, что человек видит то, чего нет, и об этом
   лучше сказать.
7. Удалённый пост исчезает отовсюду: из ленты, со своего адреса и
   вместе со своими лайками и комментариями. Отдельного счётчика постов
   в сервисе нет, поэтому «пересчитывать» после удаления нечего; у
   соседних постов их числа не меняются. Курсор ленты от этого не
   ломается: он указывает на место, а не на строку
   ([ADR-0015](../docs/adr/0015-feed-paginated-by-cursor.md)).
8. Проверки идут в этом порядке: сначала токен, потом существование,
   потом «своё ли». Поэтому запрос без токена к чужому посту — `401`,
   а удаление несуществующего чужого поста — `404`.
9. То, что пост чужой, сервис говорит прямо — `403`, а не «такого поста
   нет». Лента одна на всех, чужой пост и так виден каждому, и прятать
   его существование не от кого ([004-feed](004-feed.md)).
10. Комментарий удаляется по адресу своего поста: пара «пост и
    комментарий» должна сойтись. Комментарий, существующий, но лежащий
    под другим постом, — это `404`, а не удаление.
11. Ответ на удаление — пустой: `204`. Отдавать нечего, а пост, которого
    больше нет, в ответ не положишь.
12. В приложении удаление спрашивает подтверждение — «удалить
    безвозвратно?» — и только после согласия уходит на сервис
    ([ADR-0007](../docs/adr/0007-hard-delete.md)). «Удалить» видно
    только у своего.
13. Удалять может только вошедший; без токена нет ничего
    ([001-auth](001-auth.md)).

## Вне рамок (Out of scope)

- **Удаление чужого**: это жалоба и ручное решение владельца
  ([008-reports](000-overview.md)).
- **Отмена удаления и корзина**: удаление жёсткое
  ([ADR-0007](../docs/adr/0007-hard-delete.md)); восстановление — из
  ночной резервной копии, и это не фича приложения
  ([ADR-0005](../docs/adr/0005-no-staging-forward-only-migrations.md)).
- Редактирование вместо удаления: это
  [022-edit-block-delete](022-edit-block-delete.md).
- Удаление аккаунта и всех своих постов разом: это
  [022-edit-block-delete](022-edit-block-delete.md).
- Удаление отдельной фотографии из поста: пост неизменяем
  ([003-posts](003-posts.md), требование 15), удаляется он целиком.
- Уведомление комментаторам о том, что пост с их комментариями удалён:
  push-уведомлений в MVP нет.

## API / контракт данных

Контракт целиком — в [specs/openapi.yaml](openapi.yaml).

### `DELETE /api/posts/{postId}` — удалить свой пост

```
Authorization: Bearer <токен>

Response 204: тела нет
Response 401: { "code": "unauthorized",   "message": "..." }
Response 403: { "code": "not_your_post",  "message": "..." }
Response 404: { "code": "post_not_found", "message": "..." }
```

### `DELETE /api/posts/{postId}/comments/{commentId}` — удалить свой комментарий

```
Authorization: Bearer <токен>

Response 204: тела нет
Response 401: { "code": "unauthorized",      "message": "..." }
Response 403: { "code": "not_your_comment",  "message": "..." }
Response 404: { "code": "post_not_found",    "message": "..." }
Response 404: { "code": "comment_not_found", "message": "..." }
```

Комментарий удаляется по адресу своего поста: сначала должен найтись
пост, потом комментарий под ним, и только потом проверяется, чей он.

### Ошибки

| код | статус | когда |
|---|---|---|
| `unauthorized` | 401 | нет токена или он недействителен |
| `not_your_post` | 403 | пост есть, но он чужой |
| `not_your_comment` | 403 | комментарий есть, но он чужой |
| `post_not_found` | 404 | поста с таким идентификатором нет |
| `comment_not_found` | 404 | комментария нет или он под другим постом |

## Модель данных

Новых таблиц нет. Удаление опирается на то, что уже есть:

```
media     post_id    references posts(id) on delete cascade
post_likes post_id   references posts(id) on delete cascade
comments  post_id    references posts(id) on delete cascade
```

Одно `DELETE FROM posts WHERE id = $1 AND author_id = $2` уносит и
фотографии, и лайки, и комментарии: это уже записано в схеме
([003-posts](003-posts.md), [005-likes](005-likes.md),
[006-comments](006-comments.md)).

Ключи файлов нужны до удаления строк, поэтому удаление поста — это
`DELETE ... RETURNING` по `media` внутри той же транзакции, а сами
файлы убираются после того, как транзакция прошла: база — источник
истины, и она не должна ждать хранилище
([ADR-0011](../docs/adr/0011-files-behind-storage-interface.md)).

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Автор удаляет свой пост | `204`, поста нет ни на его адресе, ни в ленте |
| Удаление уносит фотографии поста | файлы из хранилища больше не отдаются |
| Удаление уносит лайки поста | у остальных постов лайки на месте |
| Удаление уносит комментарии поста, включая чужие | их нет вместе с постом |
| Чужой пост | `403 not_your_post`, пост остаётся |
| Повторное удаление своего поста | `404 post_not_found` |
| Несуществующий пост | `404 post_not_found` |
| Идентификатор поста не похож на UUID | `404 post_not_found` |
| Удаление поста без токена | `401 unauthorized` |
| Удаление чужого поста без токена | `401 unauthorized`: токен проверяется первым |
| Удаление несуществующего чужого поста | `404 post_not_found`: существование проверяется раньше «своё ли» |
| Автор удаляет свой комментарий | `204`, у поста `comments` уменьшилось |
| Свой комментарий под чужим постом | удаляется: комментарий свой |
| Чужой комментарий под своим постом | `403 not_your_comment`: чужое убирают жалобой |
| Чужой комментарий под чужим постом | `403 not_your_comment` |
| Повторное удаление своего комментария | `404 comment_not_found` |
| Комментарий, лежащий под другим постом | `404 comment_not_found` |
| Комментарий у несуществующего поста | `404 post_not_found` |
| Идентификатор комментария не похож на UUID | `404 comment_not_found` |
| Оба идентификатора не похожи на UUID | `404 post_not_found`: пост проверяется первым |
| Чужой комментарий по адресу другого поста | `404 comment_not_found`: пара не сошлась раньше, чем зашла речь о владении |
| Комментарий у поста, который только что удалили | `404 post_not_found` |
| Удаление комментария без токена | `401 unauthorized` |
| Остальные посты и комментарии | не трогаются ни тем, ни другим удалением |
| Лента после удаления | пост пропал, остальные на месте, курсор работает |

Требование 12 (подтверждение и «Удалить» только у своего) по HTTP не
проверяется: это приложение. Его смотрит человек по сценарию показа
([ADR-0009](../docs/adr/0009-demo-story-per-feature.md)).
