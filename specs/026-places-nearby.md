# Спецификация: населённый пункт по геолокации

## Статус
В работе

## Зачем (контекст)
Населённый пункт в профиле выбирается из подсказок справочника
([025-places](025-places.md)), но для этого надо знать, как пишется
название своего СНТ. Проще, когда приложение само предлагает пункты
рядом: человек на даче нажимает «Определить по месту» и выбирает своё
СНТ из двух-трёх ближайших.

Пункты рядом даёт тот же сервис DaData (поиск адреса по координатам),
выбранный пункт хранится так же, как в 025, — с идентификатором ФИАС.
Координаты человека нигде не сохраняются.

Задача: [#100](https://github.com/gmu-msk/moya_dacha/issues/100), эпик
[#74](https://github.com/gmu-msk/moya_dacha/issues/74).

## Пользовательский сценарий

**Дано:** человек на даче, вошёл, на сервере задан ключ DaData.

1. «Изменить профиль» → под полем «Населённый пункт» кнопка
   «Определить по месту».
2. Первый раз Android спрашивает разрешение на геолокацию; человек
   разрешает.
3. Под полем — список пунктов рядом в том же виде, что подсказки по
   названию: «снт Андрейково» и под ним «Дмитровский р-н, Московская
   обл», ниже «д Андрейково» с тем же районом.
4. Касание пункта выбирает его, дальше — как в 025: «Сохранить», и
   пункт виден в профиле.

Если человек не на даче или не дал разрешение, он ищет по названию,
как раньше.

## Функциональные требования

### Пункты рядом
1. `GET /api/places/nearby?lat=<широта>&lon=<долгота>` — пункты рядом
   с точкой, только для вошедшего (`401` без токена). Ответ `200` —
   `PlaceList` из 025: `{"places": [Place, …]}`, не больше 10.
2. `lat` от −90 до 90, `lon` от −180 до 180, оба обязательны. Нет
   параметра или он не число — `400 invalid_request` (так отвечает
   разбор запроса по контракту, ещё до проверки токена). Число вне
   пределов, `NaN` или бесконечность — `400 invalid_location`.
   Справочник в обоих случаях не спрашивается.
3. Ключа DaData нет, справочник не ответил за 5 секунд, ответил не
   `200` или ответ не разобрался — `503 places_unavailable`, как в 025.
4. Каждый отданный пункт запоминается в `places` (025, требование 5):
   его можно выбрать через `PUT /me/place`.
5. Координаты не записываются ни в базу, ни в лог сервиса.

### Как сервер спрашивает DaData
6. Запрос — `POST <адрес>/geolocate/address`, `<адрес>` и заголовки —
   как в 025 (требование 6). Тело:
   `{"lat": <lat>, "lon": <lon>, "radius_meters": 1000, "count": 20}`.
7. Ответ — тот же `{"suggestions": [...]}`; нет поля `suggestions` —
   пусто. Подсказки здесь — дома и участки рядом с точкой, а пункт
   берётся из полей подсказки `data`:
   - есть `settlement_fias_id` — пункт это населённый пункт (сюда же
     DaData кладёт СНТ): `id` = `settlement_fias_id`, `name` =
     `settlement_with_type`;
   - иначе есть `city_fias_id` — город: `id` = `city_fias_id`,
     `name` = `city_with_type`;
   - иначе подсказка пропускается; пропускается и с пустым `name`.
8. `area` — через «, » непустые `city_with_type` (только когда пункт —
   населённый пункт, а не сам город), `area_with_type`,
   `region_with_type`, в этом порядке; часть, совпадающая с `name` или
   с уже взятой, пропускается. Пример: `settlement_with_type`
   «снт Андрейково», `area_with_type` «Дмитровский р-н»,
   `region_with_type` «Московская обл» → `area` «Дмитровский р-н,
   Московская обл»; город Москва (`city_with_type` и `region_with_type`
   — «г Москва») → `area` пустая.
9. Повтор `id` пропускается (рядом много домов одного СНТ), порядок —
   как в ответе справочника, в ответ идут первые 10.

### Как это видно из Go (для тестов)
10. Адрес и ключ — те же `api.Config.PlacesURL` и `PlacesKey` (025,
    требование 14).

### Приложение
11. Под полем «Населённый пункт» (когда пункт не выбран) — кнопка
    «Определить по месту».
12. Касание: служба геолокации выключена — «Включите геолокацию в
    настройках телефона»; разрешения нет — приложение его просит; отказ
    — «Нет доступа к месту. Найдите пункт по названию». Место ищется не
    дольше 15 секунд, не нашлось — «Не удалось определить место».
13. Есть координаты — запрос `GET /places/nearby`, список под полем в
    том же виде и с тем же выбором касанием, что подсказки по названию
    (025, требования 15–16). Пусто — «Рядом ничего не нашлось. Найдите
    пункт по названию»; `503` или нет сети — «Подсказки сейчас
    недоступны».
14. Набор текста в поле убирает список пунктов рядом и показывает
    подсказки по названию.
15. Разрешение — на примерное и точное место (`ACCESS_COARSE_LOCATION`,
    `ACCESS_FINE_LOCATION`); фоновой геолокации нет. Пока человек не
    нажал кнопку, приложение о геолокации не спрашивает.

## Вне рамок (Out of scope)
- Карта и выбор точки на ней.
- Автоматическое определение места без кнопки, геолокация в фоне.
- Расстояние до пункта и сортировка по расстоянию сверх той, что даёт
  справочник.
- Геометка поста — [#75](https://github.com/gmu-msk/moya_dacha/issues/75).

## API / контракт данных

```
GET /api/places/nearby?lat=56.3412&lon=37.5203
    → 200 PlaceList | 400 invalid_location | 401 | 503 places_unavailable
  {"places": [
    {"id": "5f4a…", "name": "снт Андрейково", "area": "Дмитровский р-н, Московская обл"},
    {"id": "0c1d…", "name": "д Андрейково",   "area": "Дмитровский р-н, Московская обл"}]}
```

## Модель данных
Новых таблиц нет: пункты пишутся в `places` из 025.

## Ограничения и edge cases
- В радиусе километра нет ни одного адреса (лес, поле) — пустой список.
- Человек в городе — предложится город; это честный ответ, СНТ он
  найдёт по названию.
- Сборка из PR на сервере с main: ручки нет (`404`), приложение пишет
  «Подсказки сейчас недоступны».
