# Спецификация: пост-вопрос

## Статус
В работе

## Зачем (контекст)
Половина дачных разговоров начинается с вопроса: «что это за растение?»,
«что с листьями у огурцов?», «чем брызгать?». Сейчас такой пост ничем
не отличается от «первой клубники»: в ленте не видно, что человек ждёт
ответа, и не видно, ответили ему уже или нет. А когда ответ нашёлся,
следующий с той же бедой должен перечитать весь разговор, чтобы понять,
что помогло.

Пост-вопрос — обычный пост с отметкой «Вопрос». У вопроса есть статус
«Решён» / «Не решён», и автор может отметить комментарий, который стал
решением: он подсвечивается в разговоре.

Задача: [#115](https://github.com/gmu-msk/moya_dacha/issues/115), эпик
[#74](https://github.com/gmu-msk/moya_dacha/issues/74), из идей
[#53](https://github.com/gmu-msk/moya_dacha/issues/53).

## Пользовательский сценарий

**Дано:** Николай вошёл, у него на огурцах пожелтели листья.

1. Николай выкладывает фото и включает переключатель «Вопрос». Под ним
   подсказка: «Отметьте, если это вопрос — например «что это за
   растение» или «что с ним», — чтобы другие могли ответить, а вы —
   отметить решение».
2. В ленте над фото его поста — плашка «Вопрос» и статус «Не решён».
3. Анна открывает пост. В поле комментария вместо обычной подсказки —
   «Напишите свой ответ». Она пишет «Это мучнистая роса, брызгайте
   содой».
4. Николай открывает свой пост. У каждого комментария — кнопка-галочка
   «Отметить как решение». Он отмечает ответ Анны: комментарий подсвечивается
   и получает метку «Решение», статус вопроса — «Решён».
5. Через день оказывается, что помог совет Петра. Николай отмечает его
   комментарий — метка переезжает к Петру, вопрос остаётся решённым.
6. Если Николай разобрался сам, он нажимает «Отметить решённым» под
   постом без отметки комментария; передумал — «Ещё не решён».

**Тогда:** в ленте видно, кто ждёт помощи, а у решённого вопроса ответ
виден сразу, без чтения всего разговора.

**Если связь пропала** — статус и метка остаются как были, и человек
видит, что изменить не удалось.

## Функциональные требования

1. Пост-вопрос задаётся при публикации полем `question: true`. Без поля
   или с `false` пост обычный. Сделать вопросом уже опубликованный пост
   или наоборот нельзя.
2. У поста три поля: `question` — вопрос ли это, `solved` — решён ли
   вопрос, `answer_comment_id` — комментарий-решение или `null`. Они
   приходят везде, где приходит пост: в ленте (всех вкладках, ленте
   тэга и группы), в постах профиля, в «Сохранённых», на самом посте,
   в ответах на лайк, закладку и правку подписи. У обычного поста —
   `false`, `false`, `null`. Свежий вопрос в ответе на публикацию —
   `true`, `false`, `null`.
3. Статус «Решён» — это `solved: true`. Отметка комментария-решения
   всегда ставит `solved: true`; решённым вопрос можно сделать и без
   отметки комментария.
4. Менять статус и отметку может только автор поста. Остальным, кто
   видит пост, статус и отметка видны, но кнопок у них нет; сервис
   отвечает им `403 not_your_post`.
5. `PUT /api/posts/{id}/solved` с `{"solved": true}` делает вопрос
   решённым, отметку комментария не трогает. С `{"solved": false}` —
   нерешённым и снимает отметку комментария. Повтор того же значения
   ничего не меняет и не ошибка.
6. `PUT /api/posts/{id}/answer` с `{"comment_id": "…"}` отмечает
   комментарий решением: `answer_comment_id` — он, `solved: true`.
   Прежняя отметка, если была, снимается: решение у вопроса одно. Свой
   комментарий автор тоже может отметить — бывает, что разобрался сам
   и написал как.
7. `DELETE /api/posts/{id}/answer` снимает отметку и возвращает вопрос
   в «Не решён». Снять отметку, которой не было, — не ошибка: вопрос
   становится нерешённым.
8. Отметить можно только комментарий под этим постом, который автор
   поста видит. Комментарий чужого поста, несуществующий, удалённый или
   скрытый блокировкой ([022](022-edit-block-delete.md), требование 13)
   — `404 comment_not_found`.
9. Статус и отметка есть только у вопроса: на обычном посте все три
   ручки отвечают `400 not_a_question`.
10. Порядок проверок у трёх ручек: токен, пост (невидимый — как
    несуществующий, `404 post_not_found`), «свой ли», вопрос ли, потом
    поля тела и комментарий. Тело, которое вовсе не разбирается как
    JSON, отклоняется раньше всех проверок — `400 invalid_request`, как
    у любой ручки сервиса.
11. Комментарий-решение удалили — им самим
    ([007-deletion](007-deletion.md)), владельцем сервиса
    ([023-moderation](023-moderation.md)) или вместе с аккаунтом
    ([022](022-edit-block-delete.md)): отметка снимается, вопрос
    возвращается в «Не решён». Решение пропало — вопрос снова открыт.
    Удаление другого комментария статус не трогает.
12. Правка текста комментария-решения отметку не снимает.
13. В приложении на экране «Новый пост» — переключатель «Вопрос»
    с подсказкой из сценария, шаг 1. По умолчанию выключен.
14. У вопроса в ленте (над фото) и на экране поста — плашка «Вопрос» и рядом
    статус: «Решён» со значком галочки или «Не решён» со значком часов.
    Статус различается словом и значком, не только цветом
    ([000-ui](000-ui.md), правило 7).
15. На экране своего вопроса под плашкой — кнопка «Отметить решённым»
    или «Ещё не решён», смотря по статусу. В ленте кнопки нет: там
    только видно.
16. У каждого комментария своего вопроса — кнопка-галочка с подсказкой
    «Отметить как решение»; у уже отмеченного она закрашена, подсказка —
    «Снять отметку решения». У чужого вопроса этой кнопки нет.
17. Комментарий-решение в разговоре стоит на своём месте, подсвечен
    фоном и с меткой «Решение» со значком галочки над текстом.
18. Поле комментария под вопросом подсказывает «Напишите свой ответ»,
    под обычным постом — как было.
19. Статус и отметка в приложении меняются сразу, не дожидаясь сервиса;
    при ошибке возвращаются как было и человек видит сообщение. Пост
    в приложении один: решённый на экране поста виден решённым и в ленте.
20. Сборка из PR ходит и на сервер с `main`, где вопросов ещё нет: три
    поля в контракте не обязательные, без них пост — обычный.

## Вне рамок (Out of scope)

- **Уведомление** автору комментария, что его ответ отметили решением,
  и всем ответившим, что вопрос решён. Если понадобится — отдельной
  задачей поверх [014-notifications](014-notifications.md).
- **Лента «Нерешённые вопросы»** и фильтр по вопросам.
- **Перевод уже опубликованного поста** в вопрос и обратно.
- **Несколько решений** у одного вопроса и голоса за ответы.
- **Закрепление решения сверху** разговора: решение подсвечивается на
  своём месте, порядок разговора не меняется
  ([006-comments](006-comments.md), требование 5).
- Вопросы в дашборде.

## API / контракт данных

Контракт целиком — в [specs/openapi.yaml](openapi.yaml).

### Публикация

К телу `POST /api/posts` добавилось необязательное поле:

```
{ "media_ids": [...], "caption": "Что с огурцами?", "question": true }
```

### Пост в ответе

```
{
  …,
  "question": true,
  "solved": true,
  "answer_comment_id": "7f4e1a90-…"
}
```

Сервер с вопросами отдаёт все три поля всегда.

### `PUT /api/posts/{postId}/solved` — статус вопроса

```
Authorization: Bearer <токен>

{ "solved": true }

Response 200: пост целиком, как у GET /api/posts/{id}
Response 400: { "code": "not_a_question",  "message": "..." }
Response 400: { "code": "invalid_request", "message": "..." }
Response 401: { "code": "unauthorized",    "message": "..." }
Response 403: { "code": "not_your_post",   "message": "..." }
Response 404: { "code": "post_not_found",  "message": "..." }
```

Тело без `solved` или не разбирается — `400 invalid_request`.

### `PUT /api/posts/{postId}/answer` — отметить решение

```
Authorization: Bearer <токен>

{ "comment_id": "7f4e1a90-…" }

Response 200: пост целиком
Response 400: { "code": "not_a_question",    "message": "..." }
Response 400: { "code": "invalid_request",   "message": "..." }
Response 401: { "code": "unauthorized",      "message": "..." }
Response 403: { "code": "not_your_post",     "message": "..." }
Response 404: { "code": "post_not_found",    "message": "..." }
Response 404: { "code": "comment_not_found", "message": "..." }
```

Тело без `comment_id`, с пустым или не разбирается — `400 invalid_request`;
`comment_id` не похож на UUID — `404 comment_not_found`.

### `DELETE /api/posts/{postId}/answer` — снять отметку

```
Authorization: Bearer <токен>

Response 200: пост целиком
Response 400: { "code": "not_a_question", "message": "..." }
Response 401: { "code": "unauthorized",   "message": "..." }
Response 403: { "code": "not_your_post",  "message": "..." }
Response 404: { "code": "post_not_found", "message": "..." }
```

### Ошибки

| код | статус | когда |
|---|---|---|
| `unauthorized` | 401 | нет токена или он недействителен |
| `post_not_found` | 404 | поста нет или смотрящему он не виден |
| `not_your_post` | 403 | пост виден, но он чужой |
| `not_a_question` | 400 | пост — не вопрос |
| `invalid_request` | 400 | тело не разбирается или в нём нет нужного поля |
| `comment_not_found` | 404 | комментария нет, он под другим постом или скрыт от автора блокировкой |

## Модель данных

```
posts
  + question          boolean not null default false
  + solved            boolean not null default false
  + answer_comment_id uuid    null references comments(id) on delete set null
```

Отметка — ссылка на комментарий у поста, а не флаг у комментария: так
«решение у вопроса одно» держит сама модель. Когда ссылка обнуляется —
ручкой или удалением комментария, — триггер возвращает `solved` в
`false` (требования 7 и 11): одно правило для всех путей удаления, без
памяти о них в каждом обработчике. Почему так —
[ADR-0030](../docs/adr/0030-question-status-on-the-post.md).

## Ограничения и edge cases

| ситуация | поведение |
|---|---|
| Публикация с `question: true` | `201`, `question: true`, `solved: false`, `answer_comment_id: null` |
| Публикация без `question` или с `false` | `question: false`, `solved: false`, `answer_comment_id: null` |
| Поля в ленте, постах профиля, «Сохранённых», на посте, в ответе на лайк | `question`, `solved`, `answer_comment_id` есть |
| Автор: `solved: true` | `200`, `solved: true`, `answer_comment_id` не меняется |
| Автор: `solved: false` при отмеченном решении | `200`, `solved: false`, `answer_comment_id: null` |
| Повтор `solved` с тем же значением | `200`, ничего не меняется |
| Тело `{}` или не JSON у `solved` | `400 invalid_request` |
| Автор отмечает чужой комментарий | `200`, `solved: true`, `answer_comment_id` — он |
| Автор отмечает свой комментарий | `200`, отмечается |
| Отметка другого комментария | `answer_comment_id` — новый, прежний не отмечен |
| Повторная отметка того же | `200`, ничего не меняется |
| Отметка при `solved: true` без решения | `answer_comment_id` ставится, `solved: true` |
| `DELETE /answer` при отмеченном | `200`, `answer_comment_id: null`, `solved: false` |
| `DELETE /answer` без отметки при `solved: true` | `200`, `solved: false` |
| `DELETE /answer` без отметки при `solved: false` | `200`, ничего не меняется |
| Комментарий под другим постом | `404 comment_not_found` |
| Комментария нет / `comment_id` не UUID | `404 comment_not_found` |
| Комментарий того, с кем у автора блокировка | `404 comment_not_found` |
| Тело без `comment_id` | `400 invalid_request` |
| Не автор: любая из трёх ручек | `403 not_your_post`, ничего не меняется |
| Обычный пост: любая из трёх ручек | `400 not_a_question` |
| Чужой обычный пост | `403 not_your_post` (сначала «свой ли») |
| Свой обычный пост, тело `{}` | `400 not_a_question` (сначала «вопрос ли») |
| Пост не виден / его нет / id не UUID | `404 post_not_found` |
| Без токена, в том числе к несуществующему посту | `401 unauthorized` |
| Решение удалил его автор | `answer_comment_id: null`, `solved: false` |
| Решение удалил владелец сервиса из дашборда | `answer_comment_id: null`, `solved: false` |
| Удалили аккаунт автора решения | `answer_comment_id: null`, `solved: false` |
| Удалили другой комментарий | статус и отметка не меняются |
| Правка текста решения | отметка остаётся |
| Правка подписи вопроса | `question`, `solved`, `answer_comment_id` не меняются |
| Другой пользователь смотрит решённый вопрос | видит `solved: true` и `answer_comment_id` |

Требования 13–20 — про приложение, их смотрит человек по сценарию показа
([ADR-0009](../docs/adr/0009-demo-story-per-feature.md)).
