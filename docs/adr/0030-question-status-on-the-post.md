# 0030. Статус вопроса и отметка решения — у поста, сброс — триггером

Пост-вопрос ([specs/033-question-posts.md](../../specs/033-question-posts.md))
— обычный пост с отметкой «Вопрос», статусом «Решён» / «Не решён» и,
по желанию, комментарием-решением.

## Контекст

Нужно было решить три вещи: отдельная ли это сущность, где хранить
отметку решения и как статус переживает удаление комментария-решения.
Комментарий удаляется тремя путями: самим автором
([007](../../specs/007-deletion.md)), владельцем из дашборда
([023](../../specs/023-moderation.md)) и вместе с аккаунтом
([022](../../specs/022-edit-block-delete.md)) — каскадом в базе, мимо
обработчиков комментариев.

## Решение

**Вопрос — это пост с флагом, а не новая сущность.** Три столбца
у `posts`: `question`, `solved`, `answer_comment_id`. Лента, видимость,
лайки, закладки, жалобы и удаление работают с вопросом без изменений.

**Отметка — ссылка у поста, а не флаг у комментария.** «Решение у
вопроса одно» тогда держит сама модель: отметка другого комментария —
это перезапись одной ссылки, без снятия старого флага в той же
транзакции. Комментарий в ответе не меняется: какой из них решение,
клиент узнаёт из поста, который у него и так есть.

**`solved` хранится отдельно от ссылки.** Решённым вопрос может быть и
без отмеченного комментария — человек разобрался сам.

**Пропала ссылка — вопрос снова открыт, и это делает база.** Внешний
ключ `on delete set null` обнуляет ссылку при любом удалении
комментария, а триггер `BEFORE UPDATE OF answer_comment_id` на `posts`
при переходе ссылки из значения в `null` ставит `solved = false`. Одно
правило для всех путей удаления, включая будущие, вместо проверки
в каждом обработчике.

## Последствия

- Любой `UPDATE posts`, обнуляющий `answer_comment_id`, сбрасывает
  статус. Сделать «решён, но без отметки» из отмеченного можно только
  в два шага, и такой ручки нет: снятие отметки по спецификации и так
  открывает вопрос.
- Флаг `question` нельзя сменить после публикации: ручки для этого нет.
  Если понадобится, это отдельная ручка, а модель уже готова.
- Старые сборки приложения не видят вопросов: три поля в контракте не
  обязательные, без них пост показывается обычным.
