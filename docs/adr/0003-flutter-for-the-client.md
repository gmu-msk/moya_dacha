# 0003. Клиент на Flutter, хотя MVP только под Android

MVP выходит только на Android, и нативный Kotlin + Compose дал бы для него
лучший результат. Тем не менее клиент пишется на Flutter, потому что iOS —
обязательство проекта, а не пожелание, и переписывание клиента под вторую
платформу было бы не портом, а вторым проектом.

## Почему не React Native

Сопоставимый по возможностям вариант, и у него был сильный аргумент: общий
TypeScript с бэкендом, то есть общие типы контракта. От этого аргумента
отказались вместе с выбором Go (см. ADR-0001), а генерация клиента из
OpenAPI возвращает большую часть той же гарантии.

Что перевесило при прочих равных:

- **Устойчивость к устареванию ИИ-генерации.** Экосистема React Native
  раздроблена и быстро дрейфует (Expo против bare, смены навигации,
  новая архитектура); ИИ уверенно генерирует код под версии двухлетней
  давности. Flutter монолитнее, и сгенерированный код чаще просто работает.
- **Профиль нагрузки.** Приложение — по сути бесконечная лента фотографий;
  прокрутка такого списка на дешёвом Android во Flutter стабильнее и требует
  меньше ручной возни с кэшем изображений.
- **Аудитория.** Дачники 50+ — это старые и слабые телефоны чаще среднего,
  и любые подтормаживания будут списаны на приложение.

## Следствия

Общего языка между клиентом и сервером нет; синхронность контракта
обеспечивается генерацией из `specs/openapi.yaml`, а не компилятором
одного проекта.
