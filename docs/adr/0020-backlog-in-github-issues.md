# 0020. Бэклог — задачи GitHub, в работу идёт только одобренное владельцем

Код пишет ИИ, а решает, что делать, владелец. Нужны место, куда стекаются
идеи и баги из всех каналов (приложение, Telegram, сам владелец), и ворота,
через которые из этого места что-то попадает в работу.

## Решение

Бэклог — задачи (issues) этого репозитория. Уровни плана:

* **этап** — задача с меткой `этап`, её части — подзадачи GitHub; прогресс
  этапа виден по отмеченным подзадачам;
* **фича или работа** — подзадача этапа;
* **спецификация и PR** — как раньше, PR закрывает задачу через
  `Closes #N`.

Состояние — меткой: `входящее` → `одобрено` → `в работе` → `на проверке`
→ закрыта; сбоку `отложено`. Список меток — `.github/labels.txt`, прогон
«Бэклог» заводит их и не даёт меткам состояния противоречить друг другу.

**Ворота.** ИИ берёт задачу только с меткой `одобрено` и только по команде
владельца. Всё, что приходит от людей, получает `входящее` и ждёт.

## Почему не Linear, Notion или отдельная доска

PR, CI, сборки и сам ИИ уже живут в GitHub, задача закрывается мерджем PR
без синхронизации. Приложение GitHub на телефоне показывает задачи
и метки, этого достаточно для одного владельца. Вторая система добавила
бы перенос задач туда и обратно ради двадцати человек.

Доска GitHub Projects не заведена: метки дают те же колонки фильтром,
а доску при желании владелец добавит сам поверх тех же меток.

## Следствия

* Людям без доступа к репозиторию задачу заводит бот или сервер, а не они
  сами; им сообщают номер и потом — что идея вышла.
* Изменение процесса — правка этого ADR и `.github/labels.txt`.
