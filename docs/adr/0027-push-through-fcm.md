# 0027. Пуши — через FCM HTTP v1 из самого сервиса, очередь в базе

Раздел «Уведомления» ([specs/014-notifications.md](../../specs/014-notifications.md))
жил без пушей: в MVP их не было ([specs/000-overview.md](../../specs/000-overview.md)).
Задача [#50](https://github.com/gmu-msk/moya_dacha/issues/50) их добавляет
([specs/024-push.md](../../specs/024-push.md)).

## Решение

**Доставка — Firebase Cloud Messaging, HTTP v1 API.** На Android без
Google Play пушей по сути нет, а FCM на телефонах тестировщиков уже стоит.
Legacy API (серверный ключ) Google закрыл в 2024 году; v1 требует
OAuth-токен сервисного аккаунта. Токен сервис получает сам: JWT, подписанный
ключом аккаунта, меняется на токен по `token_uri` из ключа. Библиотек
Google ради этого в сервис не тянем: это полсотни строк на стандартной
библиотеке Go, а `firebase-admin-go` притащил бы gRPC и половину
Google Cloud SDK.

**Отправка — из сервиса, через очередь в базе.** События раздела пишут
триггеры базы (014). Ещё один триггер кладёт строку в `push_queue`, если
у получателя есть телефон, а горутина сервиса раз в секунду шлёт то, что
пролежало `PUSH_DELAY` (10 секунд). Отменённое событие уносит свою строку
каскадом — лайк, снятый сразу, пуша не даёт. Отправка из хендлера не
годится: лайк ставится в нескольких местах, и медленный Google держал бы
ответ приложению. Очередь в базе, а не в памяти, переживает перезапуск
сервиса при деплое.

**Токен телефона привязан к сессии**, а не к человеку: выход из аккаунта
уносит токен каскадом, и пуши чужого аккаунта на телефон не приходят.

**Настройки Firebase в APK — из секрета, не из репозитория.** Репозиторий
публичный; `google-services.json` кладёт в сборку CI из секрета
`GOOGLE_SERVICES_JSON`, а Gradle переносит из него в ресурсы ровно те
строки, что ищет Firebase (`google_app_id`, `google_api_key`,
`gcm_defaultSenderId`, `project_id`). Плагин `com.google.gms.google-services`
не нужен: он падает, когда файла нет, а локальная и эмуляторная сборка
должны собираться без него. Инициализация из ресурсов, а не из Dart,
нужна для пушей при закрытом приложении: процесс тогда поднимает сам
Firebase, и Dart-кода, который передал бы настройки, ещё нет.

**Сеть.** В Google сервис идёт напрямую. Если соединение не открылось
и задан `PUSH_PROXY`, он переходит на SSH-туннель до второго VPS
([ADR-0022](0022-telegram-bot-inside-the-service.md)) и ходит им до
перезапуска. С прода `api.telegram.org` не открывался, а открывается ли
Google, из облачной сессии проверить нельзя — так пуши работают в обоих
случаях, а туннель не становится лишней точкой отказа, если он не нужен.

## Цена

- Пуши зависят от Google: на телефоне без Google Play их не будет.
  Раздел «Уведомления» при этом работает как прежде.
- Firebase заводит владелец руками: проект, приложение, ключ сервисного
  аккаунта, два секрета. Без них фича молча выключена.
- iOS потребует ключа APNs в том же проекте Firebase; код сервиса
  не изменится.
- Пуш уходит на 10 секунд позже события: цена того, что отменённое
  действие не звенит.
