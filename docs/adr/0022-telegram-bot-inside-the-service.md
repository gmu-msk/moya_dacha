# 0022. Telegram-бот живёт в сервисе; тревоги — в личку, сборки — в группу

Владелец узнавал о тревогах из задач GitHub раз в два часа
([ADR-0019](0019-dashboard-inside-the-service.md)), а тестировщики о новой
сборке — только если им скажут. 26.09 владелец решил, что сборки и тревоги
идут через Telegram ([specs/018-telegram-bot.md](../../specs/018-telegram-bot.md)).

## Решение

Бот — пакет `backend/internal/telegram` того же бинарника, не отдельный
процесс. Обновления он читает long polling (`getUpdates`): сервис за Caddy
один, и webhook добавил бы только ещё один открытый адрес.

* **Тревоги** — владельцу в личку. Сервис сам считает их раз в минуту и
  пишет, только когда набор тревог изменился.
* **Сборки main** — в группу тестировщиков, с «Что нового»: файлом, а если
  APK больше 50 МБ — ссылкой на `app.apk` (дополнено 2026-09-27: release-APK
  со всеми архитектурами лимит перерос, и сборки молча не доходили).
  Отправляет команда `build-notify` на сервере, её зовёт деплой.
* **Сборки PR** — владельцу в личку ссылкой: debug-APK больше 50 МБ,
  файлом его Telegram не примет.
* **Сторож** — прогон «Дашборд» в GitHub Actions остаётся. Если лёг весь
  VPS, бот ничего не пришлёт, а задача «алерт» появится.

Чаты привязываются командами: `/start` в личке и `/group` в группе от
владельца. Владелец задан ником (`TELEGRAM_OWNER`): номер своего чата он не
знает, а ник знает, и в Telegram ник уникален. Токен — секрет репозитория
`TELEGRAM_BOT_TOKEN`, на сервер он идёт через stdin, а не командной строкой.

Дополнение 2026-09-26: с нашего VPS `api.telegram.org` не открывается
(таймаут соединения). Бот ходит в Bot API через SSH-туннель до второго
VPS Матвея, откуда Telegram открыт: служба `moya-dacha-relay` на проде
держит `ssh -D`, бот идёт через этот SOCKS-прокси (`TELEGRAM_PROXY`). На
втором VPS не нужны ни порты 80/443 (они там заняты), ни root, ни свои
программы, а TLS остаётся сквозным до Telegram. Бот остаётся в сервисе:
ему нужны база, тревоги и замеры диска прода. Если прод переедет туда, где
Telegram открыт, секрет `RELAY_HOST` можно удалить и остановить службу.

## Цена

Бот говорит только с владельцем: команды тестировщиков он пропускает.
Какие тревоги уже отправлены, бот помнит только в памяти: после перезапуска
сервиса текущие тревоги придут ещё раз. Это лучше, чем таблица ради одной
строки.
