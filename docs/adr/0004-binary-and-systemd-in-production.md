# 0004. В проде — бинарник и systemd, а не контейнеры

На VPS приложение запускается как один статический бинарник под systemd,
Postgres и Caddy ставятся из пакетов. Docker используется только в разработке
и в CI — там, где нужен одноразовый Postgres для тестов. Это сознательное
отступление от контейнеризованного деплоя, которое иначе выглядело бы
как недоделка.

## Почему

Go выбирался в том числе ради single-binary деплоя — это момент, когда за
многословность языка платят обратно. Systemd перезапускает сервис при падении
и после ребута, Caddy сам получает и продлевает TLS-сертификат; всё это три
конфига, которые потом не трогают.

Главный аргумент против — паритет окружений (в тестах Postgres из контейнера,
в проде из пакетов; версии приходится держать одинаковыми вручную). Он признан
менее важным, чем реальный риск: чинить прод будет один человек, ночью и
наспех, и в этом режиме `journalctl -u` выигрывает у слоя контейнеров.

## Следствия

- Деплой запускается **только из GitHub Actions и только с `main`** — в прод
  может попасть лишь то, что прошло гейт из ADR-0002.
- Мажорная версия Postgres в docker-compose для тестов и на VPS должна
  совпадать; за этим следят вручную.
- Приватный ключ для SSH-деплоя хранится в секретах GitHub.
