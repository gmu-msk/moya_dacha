# 0021. Все сборки APK подписаны одним ключом, и он лежит на VPS

Android ставит новую сборку поверх старой, только если у них одна подпись
и номер сборки не меньше. До этого каждую сборку подписывал debug-ключ
своего раннера CI, и тестировщику приходилось удалять приложение вместе
со входом (specs/017-app-updates.md).

## Решение

Один ключ подписи на все сборки для телефона: release-сборку из main и
debug-сборку из PR. Так сборка из PR встаёт поверх сборки из main и
наоборот.

Ключ хранится на VPS в `/var/lib/moya-dacha/signing/key.env` (только root).
Сборка берёт его по SSH тем же ключом, которым идёт деплой
(`deploy/signing-key.sh`), и стирает с раннера после сборки. Первая сборка,
не нашедшая ключа, создаёт его сама; две одновременные сохранят один.

Номер сборки — минуты от 2026-01-01 UTC: он растёт между сборками любых
workflow, а номер прогона у каждого workflow свой.

## Почему не секреты GitHub

Положить файл в секреты может только владелец и только руками: создать
ключ на компьютере, перевести в base64, вставить в настройки. С телефона
этого не сделать, а у CI прав на запись секретов нет. VPS и так
единственное место, где живёт прод, и доступ к нему у CI уже есть.

## Цена

Ключ лежит на том же диске, что и всё остальное. Пропадёт VPS — пропадёт
и ключ, и всем один раз придётся удалить приложение и поставить заново.
Копия ключа наружу — вместе с копией бэкапов, когда для них появится
хранилище (ADR-0005). Сборки на машине разработчика по-прежнему подписаны
его debug-ключом и поверх сборок CI не встают.
