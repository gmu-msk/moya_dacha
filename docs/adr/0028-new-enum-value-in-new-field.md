# 0028. Новое значение перечисления в ответе — новым полем

Видимость поста ([specs/013-post-visibility.md](../../specs/013-post-visibility.md))
— перечисление `all | friends | me`. Задача
[#109](https://github.com/gmu-msk/moya_dacha/issues/109) добавляет
четвёртый вариант — «только участники группы»
([specs/031-group-visibility.md](../../specs/031-group-visibility.md)).

## Контекст

Сгенерированный Dart-клиент разбирает перечисление строго: незнакомое
значение в ответе — исключение, и старая сборка падает на всей ленте, а не
на одном посте. С этим уже столкнулись в группах (#107). Сборки у
тестировщиков обновляются не сразу, а сборка из PR ходит и на сервер
с main.

## Решение

**Старое поле остаётся из старых значений, новое — отдельным полем.**
`Post.visibility` у поста группы — `friends` (старая сборка покажет
«друзьям»), у поста удалённой группы — `me`. Группа видимости — в новом
необязательном поле `visibility_group`; новая сборка смотрит сначала
в него.

**В запросе — безопасный запасной вариант.** Группу видимости приложение
шлёт новым полем `visibility_group_id`, а в старом `visibility` — `me`.
Сервер с фичей старое поле тогда не учитывает; сервер без неё пропустит
незнакомое поле и выложит пост «только мне», а не всем. Ошибка в сторону
скрытности, а не огласки.

В базе значение одно и честное: `posts.visibility = 'group'` плюс
`visibility_group_id`. Перевод в старое поле — только в ответе.

## Последствия

- Старая сборка не падает и не открывает пост тем, кому он не виден:
  проверка видимости одна, на сервере.
- Старая сборка подписывает пост группы «друзьям» — неточно, но
  безопасно; пройдёт с обновлением.
- Так же добавлять и следующие значения в перечисления ответов: новое
  поле, старое — из старых значений.
