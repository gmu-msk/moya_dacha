# МояДача

Соцсеть для дачников: фото посадок и урожая, советы, лайки, общение.
MVP: Android, минимальный набор фич, тест на закрытой группе пользователей.
iOS — следующая платформа после MVP (обязательство, а не пожелание).

## Подход: Spec-Driven Development (SDD)

Прежде чем генерировать код (в т.ч. через вайбкодинг), для каждой фичи сначала
пишется спецификация — что именно должно работать, какие есть ограничения,
какой контракт API/данных. Спецификация — источник истины; код и тесты
генерируются и проверяются по ней.

Контракт API машиночитаем: `specs/openapi.yaml` — источник истины, из которого
генерируются серверные типы и роутинг (Go) и клиент (Dart). Руками пишутся
только тела хендлеров. Подробно — [ADR-0001](docs/adr/0001-spec-first-openapi.md).

### Цикл работы над фичей

1. Написать/обновить спецификацию в `specs/00X-<feature>.md` и контракт
   в `specs/openapi.yaml`.
2. Сгенерировать тесты **в отдельной сессии, по спецификации и контракту** —
   не по реализации.
3. Перегенерировать код из контракта, написать реализацию, довести тесты
   до зелёного.
4. Добавить сценарий показа в `demo/stories/00X-<feature>/`: чем фичу
   показать человеку и на каких данных ([ADR-0009](docs/adr/0009-demo-story-per-feature.md)).
5. Ветка → PR → зелёный CI → мердж в `main`.

Тесты — единственный гейт. Человек читает тесты, а не реализацию. Отсюда
главные правила ревью:

> **Изменённый тест без изменённой спецификации в том же PR — красный флаг.**
>
> **Фича без сценария показа — красный флаг.**

Если тест не проходит — чинится код. Тест правится только после правки `specs/`.
Подробно — [ADR-0002](docs/adr/0002-tests-as-the-only-gate.md).

## Структура репозитория

```
specs/          спецификации фич (проза) + openapi.yaml (контракт)
backend/        Go: cmd/, internal/, api/gen/, migrations/, tests/
mobile/         Flutter-приложение; packages/moya_dacha_api — сгенерированный клиент
docs/adr/       архитектурные решения
deploy/         systemd-юнит, Caddyfile
demo/           локальный стенд для демонстрации приложения
demo/stories/   сценарии показа user-story: по одному на фичу
```

Сгенерированный код коммитится в git; CI проверяет, что он не разошёлся
с `specs/openapi.yaml`. Руками сгенерированные файлы не правятся никогда.

Интеграционные тесты живут в отдельном пакете `backend/tests/` — чтобы доступ
к внутренностям был невозможен физически, а не по договорённости.

## Демонстрация

Каждую фичу можно посмотреть глазами, а не по зелёной галочке в CI. У каждой
user-story свой сценарий показа ([ADR-0009](docs/adr/0009-demo-story-per-feature.md)):

    make stories                  # что можно показать
    make story STORY=000-status   # показать в эмуляторе

Команда поднимает локальный стенд (Postgres, миграции, демо-данные сценария,
сервис — нужен только Docker), ставит приложение в запущенный эмулятор и
печатает список того, что надо проверить глазами.

На свой телефон приложение ставится так:

    make demo-lan                 # стенд, видимый в локальной сети
    make apk-phone-install        # APK с адресом этой машины, по USB

Подробности — в [demo/README.md](demo/README.md),
[demo/stories/README.md](demo/stories/README.md) и
[mobile/README.md](mobile/README.md). Стенд не является staging-средой: сред
по-прежнему две, локальная и прод
([ADR-0005](docs/adr/0005-no-staging-forward-only-migrations.md)).

## Технические решения

| | |
|---|---|
| Клиент | Flutter ([ADR-0003](docs/adr/0003-flutter-for-the-client.md)) |
| Backend | Go, spec-first ([ADR-0001](docs/adr/0001-spec-first-openapi.md)) |
| БД | PostgreSQL, миграции — `goose`, forward-only |
| Клиент API | Генерируется из контракта ([ADR-0008](docs/adr/0008-dart-client-generation.md)) |
| Тесты | Интеграционные по HTTP против настоящей Postgres в контейнере |
| Прод | Один бинарник + systemd + Caddy на VPS ([ADR-0004](docs/adr/0004-binary-and-systemd-in-production.md)) |
| Деплой | Только из GitHub Actions, только с `main` |
| Среды | Локальная и прод; staging нет ([ADR-0005](docs/adr/0005-no-staging-forward-only-migrations.md)) |
| Демонстрация | Локальный стенд `make demo`, сценарий показа на фичу ([ADR-0009](docs/adr/0009-demo-story-per-feature.md)) |
| Хранение фото | S3-совместимое хранилище + CDN (провайдер — TBD) |
