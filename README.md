# МояДача

Соцсеть для дачников: фото посадок и урожая, советы, лайки, общение.
MVP: Android, минимальный набор фич, тест на закрытой группе пользователей.

## Подход: Spec-Driven Development (SDD)

Прежде чем генерировать код (в т.ч. через вайбкодинг), для каждой фичи сначала
пишется спецификация — что именно должно работать, какие есть ограничения,
какой контракт API/данных. Спецификация — источник истины; код и тесты
генерируются и проверяются по ней.

Порядок работы над фичей:
1. Написать/обновить спецификацию в `specs/<feature>.md`.
2. Сгенерировать/написать код по спецификации (backend и/или mobile).
3. Проверить код на соответствие спецификации (вручную и/или тестами).
4. Зафиксировать в git только то, что прошло проверку.

## Структура репозитория

- `specs/` — спецификации фич и API-контракты (источник истины для вайбкодинга)
- `backend/` — серверная часть (API, БД, миграции)
- `mobile/` — мобильное приложение (Android, позже iOS)
- `docs/` — архитектурные решения, план запуска, заметки
